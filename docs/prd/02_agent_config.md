# 模块二：助手配置

## 模块概述

### 业务目标
管理 AI 助手的配置，包括角色设定、技能关联和权限模式，使每个助手能以不同的角色和能力执行任务。

### 核心职责
- 助手完整生命周期管理
- 助手角色设定（instructions）
- 助手技能关联
- 权限模式控制
- 助手状态管理

### 涉及角色
- 开发者（创建、编辑、删除助手）

### 核心业务对象
- **助手（Agent）** - AI 助手配置，包含名称、指令、技能、权限模式
- **助手技能关联（AgentSkill）** - 助手与技能的多对多关系

### 前置条件
- 用户已配置本地 Claude Code CLI

---

## 模块边界

### 上游模块
| 模块 | 输入 |
|------|------|
| 技能管理 | 提供可选择的技能列表 |

### 下游模块
| 模块 | 输出 |
|------|------|
| 任务管理 | 任务指派给助手后，助手执行任务 |
| 任务执行 | 领取任务时获取助手配置 |
| 对话功能 | 对话时获取助手配置 |

### 数据边界
- 一个助手可以关联多个技能
- 一个技能可以关联多个助手
- 助手配置存储在数据库，不影响本地 Claude Code 配置

### 职责边界
- 本模块不负责 Claude Code CLI 的安装
- 本模块不负责 Agent 的实际执行

## 核心流程与状态

### 助手状态流转

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│  idle    │────►│ working  │────►│  error   │
└──────────┘     └──────────┘     └──────────┘
     │                │                  │
     │                ▼                  │
     │           ┌──────────┐            │
     └──────────►│ offline  │◄───────────┘
                 └──────────┘
```

| 状态 | 说明 | 触发条件 |
|------|------|---------|
| idle | 空闲 | 初始化/任务完成后 |
| working |工作中 | 正在执行任务 |
| error | 错误 | 执行异常 |
| offline | 离线 | 助手不可用 |

### 权限模式

| 模式 | 说明 | 使用场景 |
|------|------|---------|
| bypassPermissions | 自动批准所有操作 | 完全自主执行 |
| clippings | 自动批准读操作，写操作需确认 | 半自动模式 |
| default | 每次操作需确认 | 谨慎模式 |

### 助手指派流程

```
用户选择助手创建/编辑任务
    │
    ├── 助手状态检查
    │     │
    │     ├── idle → 可指派
    │     ├── working → 提示"助手忙碌"
    │     └── offline → 提示"助手离线"
    │
    └── 任务分配给助手
         │
         ▼
    助手状态变为 working
    任务执行模块开始领取任务
```

## 功能点

### 功能 1：创建助手

**功能目标/解决的问题**
用户需要添加新的 AI 助手进行配置。

**前置条件**
- Claude Code CLI 已安装并可用

**业务规则**
- 助手名称为必填项，长度 1-100 字符
- instructions 为选填，最长 50000 字符
- max_concurrent_tasks 默认为 1
- model 为选填，不填则使用 Claude Code 默认模型
- runtime_mode 默认为 default

**交互流程**
1. 用户点击「新建助手」按钮
2. 系统弹出助手创建弹窗
3. 用户填写表单
4. 用户点击「保存」按钮
5. 系统验证必填字段
6. 保存成功后关闭弹窗，刷新列表显示新助手

**异常与边界**
- 名称为空：提示「名称不能为空」
- 名称重复：提示「助手名称已存在」
- CLI 不可用：提示「未检测到 Claude Code CLI」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 创建成功 | E2E | 填写必填字段，点击保存 | - |
| 名称必填 | E2E | 名称为空时保存 | 空白字符串 |
| 默认值正确 | 单元测试 | 不填写可选字段，查看默认值 | - |

---

### 功能 2：编辑助手

**功能目标/解决的问题**
用户需要修改已存在助手的配置。

**前置条件**
- 助手存在
- 助手状态不为 working（工作中的助手不可编辑）

**业务规则**
- 名称、instructions、技能、权限模式均可修改
- max_concurrent_tasks 和 model 可修改
- 工作中的助手不可编辑

**交互流程**
1. 用户点击助手列表中的「编辑」按钮
2. 系统弹出编辑弹窗，预填当前数据
3. 用户修改表单
4. 用户点击「保存」按钮
5. 系统保存修改
6. 关闭弹窗，刷新列表

**异常与边界**
- 工作中的助手编辑：提示「工作中的助手不可编辑」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 编辑成功 | E2E | 修改所有字段并保存 | - |
| 工作中不可编辑 | E2E | 尝试编辑 working 状态助手 | working 状态 |

---

### 功能 3：删除助手

**功能目标/解决的问题**
用户需要删除不需要的助手配置。

**前置条件**
- 助手存在
- 助手状态不为 working

**业务规则**
- 删除助手会级联删除相关的 agent_skill 关联
- 工作中的助手不可删除
- 有待执行任务的助手不可删除

**交互流程**
1. 用户点击助手列表中的「删除」按钮
2. 系统弹出确认对话框
3. 用户点击「确认删除」
4. 系统执行删除
5. 刷新列表

**异常与边界**
- 工作中的助手删除：提示「工作中的助手不可删除」
- 有待执行任务：提示「该助手有待执行任务，请先处理」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 删除成功 | E2E | 确认删除 | idle 状态 |
| 工作中不可删除 | E2E | 尝试删除 working 助手 | working 状态 |
| 级联删除关联 | 单元测试 | 删除助手后检查 agent_skill 表 | - |

---

### 功能 4：助手技能关联

**功能目标/解决的问题**
用户需要为助手配置可用的技能。

**前置条件**
- 助手存在
- 技能已创建

**业务规则**
- 支持多对多关联
- 一个助手可以有零个或多个技能
- 一个技能可以关联零个或多个助手

**交互流程**
1. 用户在编辑助手弹窗中点击「添加技能」
2. 系统弹出技能选择列表
3. 用户选择技能
4. 用户点击「保存」
5. 系统保存关联关系

**异常与边界**
- 技能不存在：提示「请先创建技能」
- 重复关联：提示「该技能已关联」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 关联成功 | E2E | 选择技能并保存 | - |
| 多技能关联 | E2E | 关联多个技能 | 5+ 技能 |
| 移除关联 | E2E | 取消技能勾选 | - |

---

### 功能 5：助手状态管理

**功能目标/解决的问题**
系统需要管理助手的状态以协调任务执行。

**前置条件**
- 助手存在

**业务规则**
- 助手空闲时状态为 idle
- 领取任务后状态变为 working
- 任务完成后状态恢复为 idle
- 执行异常时状态变为 error
- 助手不可用时状态为 offline

**交互流程**
1. 任务执行模块领取任务
2. 系统更新助手状态为 working
3. 任务执行完成/失败
4. 系统更新助手状态为 idle/error

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 状态变更正确 | 单元测试 | 领取任务后检查状态 | - |
| 状态恢复 | 单元测试 | 任务完成后检查状态 | - |
| WebSocket 广播 | E2E | 状态变更后检查 WS 消息 | - |

## 数据库设计

### 表结构

#### agent 表（助手）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | UUID | PK | 主键 |
| name | TEXT | NOT NULL, UNIQUE | 助手名称 |
| instructions | TEXT | | 角色设定/系统提示词 |
| runtime_mode | TEXT | NOT NULL, CHECK | 权限模式 |
| status | TEXT | NOT NULL, CHECK | 状态 |
| max_concurrent_tasks | INT | NOT NULL DEFAULT 1 | 最大并发任务数 |
| model | TEXT | | 指定模型（空则使用默认） |
| created_at | TIMESTAMPTZ | NOT NULL | 创建时间 |
| updated_at | TIMESTAMPTZ | NOT NULL | 更新时间 |

**CHECK 约束：**
```sql
runtime_mode IN ('bypassPermissions', 'clippings', 'default')
status IN ('idle', 'working', 'error', 'offline')
```

#### agent_skill 表（助手-技能关联）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| agent_id | UUID | NOT NULL, REFERENCES agent | 助手 ID |
| skill_id | UUID | NOT NULL, REFERENCES skill | 技能 ID |
| position | INT | NOT NULL DEFAULT 0 | 排序位置 |

**主键：** (agent_id, skill_id)

### 索引

```sql
CREATE INDEX idx_agent_status ON agent(status);
CREATE INDEX idx_agent_skill_agent ON agent_skill(agent_id);
CREATE INDEX idx_agent_skill_skill ON agent_skill(skill_id);
```

## 技术实现参考（Multica）

### Claude Code CLI 调用

助手通过 `claude -p --output-format stream-json --permission-mode {mode}` 调用，其中 `--permission-mode` 参数控制权限：

```go
// server/pkg/agent/claude.go
args := []string{
    "-p",
    "--output-format", "stream-json",
    "--input-format", "stream-json",
    "--verbose",
    "--strict-mcp-config",
    "--permission-mode", "bypassPermissions", // 从 agent.runtime_mode 读取
}
```

### 助手状态管理

```go
// server/internal/agent/service.go
type AgentService struct {
    // 状态流转：idle -> working -> idle/error
}

// 领取任务时更新状态
func (s *AgentService) SetWorking(ctx context.Context, agentID uuid.UUID) error {
    return s.db.UpdateAgentStatus(ctx, agentID, "working")
}
```

### 权限模式区别

| 模式 | --permission-mode 值 | 行为 |
|------|----------------------|------|
| bypassPermissions | bypassPermissions | 完全自动执行，无需确认 |
| clippings | clippings | 自动批准读操作，写操作需确认 |
| default | default | 每次操作需确认 |
