# 项目管理 PRD

> 状态：PRD 已确认
> 模块编号：01

## 1. 场景意图

### 1.1 业务背景与目标

forge 是以 pi 为引擎的桌面项目工作台，覆盖"项目启动 -> 对话编程"全流程。项目管理是工作台的入口能力：用户将本地代码目录注册为"项目"，在项目下创建会话开展 AI 编程。项目对齐 pi 的"当前工作目录(cwd)"概念，会话按项目组织；项目信任直接继承 pi 机制，forge 不另造权限。

### 1.2 场景清单

| 场景 ID | 场景 | 业务价值 | 必须达成 | 明确不做 |
|---|---|---|---|---|
| PM-S01 | 添加项目 | 把本地目录纳入工作台管理 | 选择目录 -> 注册 -> 出现在项目列表 | 不复制/移动源文件 |
| PM-S02 | 打开项目 | 进入项目工作区开展会话 | 从列表选择 -> 加载该项目会话 | 不在打开时自动跑任务 |
| PM-S03 | 移除项目 | 清理不再关注的项目 | 从列表移除 | 不删除用户源文件 |
| PM-S04 | 项目信任 | 安全加载项目级 pi 资源 | 首次打开含 `.pi` 资源项目时按 pi 规则询问 | 不自造权限/审批系统 |

### 1.3 边界与权限

- **不可接受方案**：删除或修改用户源文件；未经信任加载项目级扩展/设置；多角色权限系统。
- **必须满足条件**：项目 = 本地目录；项目信任流程与 pi 一致（`defaultProjectTrust` ask/always/never、`/trust`、`--approve`）；项目列表元数据由 forge 管理，会话存储交给 pi。
- **角色与权限边界**：单用户桌面应用，无多角色；项目信任由 pi 机制控制，forge 仅做询问呈现与结果回传。

### 1.4 已确认业务决策

- 项目 = pi 的 cwd 分组（对齐 pi session 组织方式）。
- 项目信任继承 pi（`defaultProjectTrust` / `/trust` / `--approve`），forge 不另造权限。
- 移除项目仅清理 forge 侧注册，不删除用户源文件，也不删除该项目已产生的 pi 会话。
- 项目只是会话的分类容器，不是活动单元；活动单元是会话（见模块 02）。

## 3. 详细设计

### 3.1 模块概述与边界

- **业务目标**：将本地目录注册为项目并组织会话，提供项目级信任的安全加载入口。
- **核心职责**：项目注册、列表维护、打开/移除、项目信任询问的 UI 呈现与决策回传。
- **核心业务对象**：项目（Project）= 本地目录绝对路径 + 元数据（别名、最近打开时间、信任状态、优先级）。
- **涉及角色**：单用户（桌面应用所有者）。
- **前置条件**：forge 已启动；被添加的本地目录存在且可访问。
- **上下游与职责边界**：
  - 上游：无（工作台入口）。
  - 下游：模块 02 会话管理（打开项目后加载该项目会话）；pi（信任机制、会话存储）。
  - 数据边界：项目元数据归 forge 自有存储；会话与消息归 pi 存储，本模块不读写。

### 3.2 核心流程与状态

```
添加项目(选目录) -> 已注册(未信任) -> 打开项目
   -> 含.pi资源且未信任? -> 是: 信任询问 -> 信任通过: 加载项目级资源, 进入工作区
                                       -> 拒绝: 不加载项目级资源, 仍进入工作区(基础能力可用)
                        -> 否: 直接进入工作区
移除项目 -> 仅删 forge 元数据 -> pi 会话保留(可重新添加项目恢复可见)
```

项目信任状态：`未信任` / `询问中` / `已信任` / `已拒绝`。信任状态由 pi 持有，forge 仅缓存展示。

### 3.3 功能点

#### 功能点：PM-S01 添加项目

- **目标**：把本地目录注册为项目，纳入工作台。
- **前置条件**：目录存在且当前用户可访问。
- **业务规则**：
  - 项目 = 本地目录绝对路径，规范化后作为唯一键。
  - 同一路径不可重复注册。
  - 不复制、不移动、不修改源文件。
  - 别名默认取目录名，用户可改。
  - 项目列表支持拖拽排序（钉扎优先级）：`priority` 升序优先，未钉扎项目按最近打开倒序排其后；新项目默认未钉扎（出现在钉扎项目之后）。
- **业务数据**：路径、别名、创建时间、最近打开时间、信任状态（初始未信任）。
- **交互与反馈**：点"添加项目" -> 调用系统目录选择器 -> 选定目录 -> 校验 -> 注册 -> 列表新增并高亮。失败时提示原因，不新增。
- **权限边界**：单用户无限制；注册不触发信任（信任在打开时按需询问）。
- **合法/非法状态流转**：未注册 -> 已注册（合法）；已注册 -> 已注册同路径（非法，拒绝）。
- **异常与边界**：目录不存在/无访问权限 -> 提示"路径无效或不可访问"，不注册；路径含符号链接 -> 规范化为真实路径后校验。
- **数据一致性与幂等**：同一路径多次添加只产生一条记录；注册只写 forge 元数据，不动源目录。
- **跨模块影响**：无（注册不触及会话）。

#### 功能点：PM-S02 打开项目

- **目标**：进入项目工作区，加载该项目会话列表。
- **前置条件**：项目已注册。
- **业务规则**：
  - 打开 = 设为当前项目，更新最近打开时间。
  - 加载该项目的会话列表（交模块 02）。
  - 首次打开且项目含 `.pi` 资源时触发信任询问（PM-S04）。
  - 打开不自动执行任何 agent 任务。
- **业务数据**：最近打开时间更新；信任状态按需流转。
- **交互与反馈**：列表点击项目项 -> 进入工作区（会话列表视图）。目录失效时提示"项目路径已失效，是否移除或重新定位"。
- **权限边界**：信任未通过时，项目级扩展/设置不加载，基础会话能力仍可用。
- **合法/非法状态流转**：已注册 -> 当前项目（合法）；当前项目目录失效（非法态，需提示修复）。
- **异常与边界**：目录被删除/移动 -> 提示路径失效，不崩溃；提供"重新定位目录"或"移除项目"出口。
- **数据一致性与幂等**：重复打开同一项目只更新最近打开时间，不产生副作用。
- **跨模块影响**：触发模块 02 加载会话列表；按需触发 PM-S04 信任询问。

#### 功能点：PM-S03 移除项目

- **目标**：从工作台列表移除不再关注的项目。
- **前置条件**：项目已注册。
- **业务规则**：
  - 仅删除 forge 侧项目元数据。
  - 不删除用户源文件。
  - **级联删除该项目名下全部会话**（v3.32 用户改判 TD-PM-05 为 B）：停运行 + 删 pi 会话文件 + 删 forge 会话记录，逐个发射 `session.removed` 供多窗口同步。
  - 幂等：重复移除同一项目无副作用（已不存在则忽略）。
- **业务数据**：forge 项目与会话记录删除；pi 会话文件删除；源文件不动。
- **交互与反馈**：项目项"移除"（下拉悬停 × 两阶段确认 / 侧栏右键确认）-> 确认后列表移除，toast 提示"项目已移除，连同 N 个会话一并删除"。
- **权限边界**：单用户；移除不触及信任状态文件。
- **合法/非法状态流转**：已注册 -> 已移除（合法）；已移除 -> 直接打开（非法，需重新添加）。
- **异常与边界**：级联删除中某会话删除失败（如 pi 侧异常）-> 整体返回 5000，已完成部分不回滚（会话删除本身不可逆，重试移除幂等继续）；原"有会话提示不阻塞"规则随 v3.32 改判作废。
- **数据一致性与幂等**：重复移除同一项目无副作用（已不存在则忽略）。
- **跨模块影响**：模块 02 会话随项目一并删除（不可逆）；源文件保留，重新添加同路径项目不会恢复已删会话。

#### 功能点：PM-S04 项目信任

- **目标**：按 pi 规则安全加载项目级 pi 资源（扩展/设置）。
- **前置条件**：项目含 `.pi` 资源；首次打开或处于未信任状态。
- **业务规则**：
  - 信任完全继承 pi（`defaultProjectTrust`、`/trust`、`--approve`），forge 不另造审批。
  - 以 **user/global 扩展**形式拦截 pi `project_trust` 事件（project-local 扩展在信任前未加载，不能用）；SDK 模式 `ctx.hasUI` 可能为 false，**不走 `ctx.ui`**，由该扩展经 forge-core 桥接 Vue 弹窗呈现（TD-PM-02）：显示项目路径与待加载资源类型，用户选择信任/不信任/本次信任，结果回传 pi。
  - 信任通过后项目级扩展/设置加载；拒绝则不加载，基础会话能力仍可用。
- **业务数据**：信任状态流转（未信任 -> 询问中 -> 已信任/已拒绝）。
- **交互与反馈**：打开项目时按需弹出信任询问弹窗 -> 用户选择 -> 回传 -> 资源加载或跳过。
- **权限边界**：未信任时项目级资源不加载，是安全硬约束，不可绕过。
- **合法/非法状态流转**：未信任 -> 询问中 -> 已信任/已拒绝（合法）；已信任 -> 加载资源（合法）；跳过询问直接加载（非法）。
- **异常与边界**：pi 未暴露可拦截的信任事件 -> 降级为 pi 默认信任行为（TD-PM-02 风险项，开发期验证）；弹窗超时未响应 -> 按 pi 默认策略处理。
- **数据一致性与幂等**：同一项目信任决策幂等，重复打开不重复询问（已信任/已拒绝的不再问）。
- **跨模块影响**：信任结果影响项目级扩展加载（forge-extensions）；信任状态由 pi 持有，forge 缓存展示。

### 3.4 页面承载

- **页面路径与访问权限**：项目列表页（工作台首页，无前置权限）；项目工作区（打开项目后）。
- **页面结构**：
```
项目列表页
┌──────────────────────────┐
│ [添加项目]                 │
│ ┌──────────────────────┐ │
│ │ 项目别名  路径  信任标记 │ │  <- 项目项（点击打开，右键移除）
│ │ 最近打开时间           │ │
│ └──────────────────────┘ │
│ ...                       │
└──────────────────────────┘
```
- **操作入口、按钮和链接**："添加项目"（触发目录选择器）；项目项点击（打开）；项目项右键/更多按钮（重命名/打开项目所在目录/移除，v3.36 增补前两者）；会话输入框项目下拉的"打开项目…"与主内容区空态按钮均直接弹系统目录选择器（v3.28 起不再经项目弹窗；v3.21 起侧栏顶部不再放置打开项目按钮，侧栏仅保留导航职责）。
- **打开项目所在目录（v3.36）**：项目右键/⋯ 菜单新增"打开项目所在目录"，经 preload shell 通道（`forge:shell:openPath`）调 Electron `shell.openPath` 用系统文件管理器打开项目目录；失败静默（返回 false），浏览器 dev mock 为 no-op。
- **表单字段与业务校验**：添加时无表单（目录选择器）；别名可编辑（非空，默认目录名）。
- **弹窗、loading、成功/失败反馈**：
  - 移除确认弹窗：触发=点移除；内容="仅移除注册，不删除源文件与会话"；操作=确认/取消。
  - 信任询问弹窗：触发=打开含 `.pi` 资源的未信任项目；内容=项目路径+待加载资源类型；操作=信任/不信任/本次信任。
  - 添加成功=列表新增高亮；失败=提示原因；目录失效=提示并提供修复出口。
- **失败时的上下文和数据保留**：操作失败不清空列表；目录选择中断返回列表原状态。

### 3.5 非功能要求

- **性能与容量**：项目列表支持 ≤1000 个项目，列表渲染 < 200ms；目录选择与注册响应 < 500ms。
- **安全与审计**：信任流程不可绕过 pi 机制；未信任资源绝不加载。
- **可用性与降级**：目录失效/无权限不崩溃，提供修复出口；信任事件拦截不可用时降级为 pi 默认行为。
- **可观测性**：信任决策（项目、决策结果、时间）记入日志，便于追溯。
- **兼容性**：项目元数据存储格式需支持后续升级迁移。
