## 1. 场景意图

### 1.1 业务背景与目标

本模块是同一套「forge 产品更新体系」需求，分两个交付层：

1. **设置页「版本更新」分区（已实现）**：用户在设置页感知 forge 产品版本，并手动把内置组件更新到最新。产品语义上只讲「forge 版本 / 内置组件」，不暴露 pi 细节（明面是产品更新，内部实现是更新共享扩展：`pi update --extensions`，经内置引擎 CLI 执行，不依赖用户安装全局 pi）。
2. **安装包与联动更新（待开发）**：forge 作为产品分发给最终用户——Windows 安装包双击即用；首次运行后台静默预装推荐组件（开箱即用、完全无感）；应用自更新（GitHub Releases，提示用户、手动点击更新）；forge 版本变化后联动静默更新组件（新引擎配新插件）。

前置结论（对话已拍板）：引擎（内置 pi SDK）随 forge 发版；插件装到共享 `~/.pi/agent`；全局 pi CLI 的检测与更新不做。

### 1.3 边界与权限

- 不可接受方案：更新过程破坏用户 `~/.pi/agent` 已有数据（models.json、settings、sessions）；更新包不可校验来源；全局 pi CLI 被检测/改动。
- 必须满足条件：预装/联动/手动更新均幂等且只增不删；自更新包完整性校验（electron-updater 内置签名/哈希校验）；离线时全部功能可用（检查更新/预装/联动失败静默，手动更新失败内联展示）。
- 角色与权限边界：单用户本机产品，无角色区分；安装写入用户目录（per-user），不需要管理员权限；组件操作只写用户自己的 `~/.pi/agent`。

### 1.4 已确认业务决策

- 明面只讲「forge 版本更新」，不暴露 pi/引擎细节（引擎版本不露出）。
- 引擎随 forge 发版，不做运行时在线替换内置 SDK。
- 插件归属共享 `~/.pi/agent`，与终端 pi 共用一份。
- 全局 pi CLI：不检测、不更新。
- 设置页更新不做检查-更新两步，直接一个更新按钮（幂等；无更新时更新器自身输出提示）。
- 更新成功 toast「更新完成」并刷新清单；失败在分区内展示错误与输出尾部（不弹 toast）。
- 预装推荐插件对客户**完全无感**：后台静默执行，UI 不出现任何「组件/插件」字样的预装提示。
- 自更新通道：**GitHub Releases**（electron-updater 对接，打 tag 即发版）。
- 预装清单：**当前 6 个插件**作为初始推荐清单（v2025-11：v3.64 曾扩至 11，因 forge 自建 `ask_user_question` 内置扩展会与之重名，v3.65 移除 `@juicesharp/rpiv-ask-user-question` 回落至 10；本次再精简至 6 — 仅保留 forge 内核必备项：`@tintinweb/pi-subagents` / `@narumitw/pi-goal` / `pi-mcp-adapter` / `pi-web-access` / `pi-compact-display` / `@juicesharp/rpiv-todo`；`@vndv/pi-codegraph` / `pi-image-view` / `pi-tool-display` / `@dietrichgebert/ponytail` 由宿主 `pi` CLI 自带 / 用户按需安装，forge 不再代为预装）。
- 两类更新两种姿态：
  - **组件（共享插件）自动更新、不用提示**：forge 版本变化触发后台静默更新；
  - **forge 版本更新包提示用户、手动点击更新**：发现新版本 → 提示 → 用户手动点击才下载安装。
- 「重启安装」点击后**弹窗确认**（含影响说明），用户确认后才执行安装重启（原型反馈 2026-09-08）。
- **安装器为向导模式**（v3.78.9 修订，反馈 2026-09-19：「首次安装要给人选择安装在什么地方」）：首次安装/手动重装显示标准「选择安装位置」页（预填 per-user 默认目录，可点「更改」自定义），页顶文案注明「所选路径不以 forge 结尾时自动安装到其下 forge 子目录」（instFilesPre 官方行为，仅提示化，不改行为；反馈 2026-09-19 第三轮）；**自动更新保持零点击**——electron-updater 恒传 `--updated --force-run`，目录页被模板 skipPageIfUpdated 跳过，「安装模式」页与结束页由 `build/installer.nsh` 钩子跳过（customInstallMode 强制 per-user；customInstall 复刻 oneClick 收尾：装完拉起应用后 Quit），安装期进度页可见。**明确不做**「静默无窗口安装」——用户只看到应用消失、过一会儿又突然跳出来，看不到进度（2026-09-14 反馈）。
- 设置页**不展示组件清单**：组件对用户完全不可见，变更明细记录于结构化日志（包名 · 旧版本 → 新版本 · 触发来源），并写入 updater-state.json 的 components 版本快照（原型反馈 2026-09-08）。

### 常规默认项（不另行确认）

- 安装写入 `%LOCALAPPDATA%`（electron-builder NSIS 默认 per-user），数据仍在 `%APPDATA%/forge`（userData），与现状一致。
- 预装/联动/手动更新均幂等：清单已列且实体已装 → 跳过；失败不阻塞启动、静默降级（手动更新失败内联展示）。

## 3. 详细设计

### 3.1 模块概述与边界

- 业务目标：设置页提供版本感知与手动组件更新（已交付）；交付可分发的 Windows 安装包、开箱即用的静默预装、提示式应用自更新与无感组件联动更新（待开发）。
- 核心职责：设置页「版本更新」分区；安装包构建与安装；首次运行组件预装；应用自更新（检查/提示/下载/重启安装）；版本变化驱动的组件联动更新。
- 核心业务对象：forge 版本、（内部）共享组件清单、安装包产物、推荐组件清单。
- 涉及角色：最终用户（普通开发者，手动更新/无感预装）、实现维护者（发布 tag/GitHub Releases 上传）。
- 前置条件：手动更新无外部前置；自更新与预装需客户端可访问 GitHub Releases（失败静默降级）。
- 上下游与职责边界：组件读写与更新器由本模块的 piRuntime 层承载（已实现）；自更新由 Electron 壳（forge-desktop）承载（待开发）；UI 只承载「forge 版本更新」语义（设置页分区）。安装包内引擎与 forge 捆绑一体发版。

### 3.2 核心流程与状态

```
设置页（已实现）
  打开分区 → pi/getInfo → 版本行 + 组件清单
  点「更新组件」→ busy → 成功 toast + 刷新 / 失败内联错误 + 输出尾部

安装与自更新（待开发）
  首次启动
    └─ 后台静默预装组件（幂等补缺）→ 完成（无 UI）
  正常运行
    ├─ 启动时 + 手动（关于页「检查更新」）：检查 forge 更新（GitHub Releases feed）
    │   ├─ 无新版 → 无提示（徽标「✓ 已是最新」）
    │   └─ 有新版 → 侧栏更新图标入口出现（found=下载图标，hover 展开「新版本」；不弹 toast）
    │        + 设置页「版本更新」分区镜像常驻新版信息与「更新」按钮
    │        └─ 用户点击「更新」（侧栏或分区）→ 下载（侧栏环即进度/分区百分比）→ 就绪（侧栏切「更新」圆图标）→ 点「重启安装」→ 确认 → 安装新版本
    └─ 启动时：forge 版本较上次变化 → 后台静默联动更新组件（失败静默）
```

自更新状态机（待开发）：`idle → checking → found → downloading → downloaded/ready → installing`；任一网络/下载失败回 `idle` 静默可重试。联动触发依据：forge 对比安装版本与 userData 记录的上次运行版本，不等则触发组件联动更新并回写。

### 3.3 功能点

#### 功能点：PU-F01 版本展示（已实现；组件清单随确认反馈移除）

- 目标：用户在设置页感知 forge 产品版本。
- 前置条件：打开设置页。

- 业务数据：forge 版本。
- 交互与反馈：打开设置即拉取；无任何加载打断。
- 权限边界：只读。
- 合法/非法状态流转：正常展示 ↔ 降级展示（不报错）。
- 异常与边界：获取失败静默降级。
- 数据一致性与幂等：只读操作。
- 跨模块影响：组件细节对 UI 不可见（含已实现的清单 UI 移除，随 dev 调整）。

#### 功能点：PU-F02 手动更新组件（已实现；展示形态调整）

- 目标：用户手动把内置组件更新到最新。
- 前置条件：设置页版本更新分区可见。
- 业务规则：「更新组件」按钮触发更新（复用内置引擎更新器，等价终端 `pi update --extensions`）；busy 态同步等待（更新器超时 10 分钟）；成功 → toast「更新完成」；失败 → 分区内错误框（message）+ 输出尾部（≤4000 字符），按钮恢复可点；**变更明细（包名 · 旧版本 → 新版本）写结构化日志，并刷新 updater-state.json 的 components 快照**；更新器输出尾部同时供成功回显/失败排查。
- 业务数据：更新器输出尾部。
- 交互与反馈：busy「更新中…」；成功 toast；失败不弹 toast、内联展示。
- 权限边界：写用户共享 `~/.pi/agent`。
- 合法/非法状态流转：busy 进出；失败回落可重试。
- 异常与边界：内置 CLI 缺失（打包裁剪）→ 直接失败并给出中文原因，不 spawn；超时/非零退出 → 失败 + 输出尾部。
- 数据一致性与幂等：更新幂等（已最新时更新器自身输出提示）；只升不降、不动用户自装项。
- 跨模块影响：更新结果即时反映到清单；终端 pi 下次启动同享新版本组件。

### 3.5 非功能要求

- 性能与容量：组件更新为用户手动触发（busy 同步等待，超时 10 分钟）；预装/联动更新后台低优先级执行，不阻塞首启可用（目标：首启 UI 可交互后 2s 内返回）；更新安装包体积随引擎而定（不设硬限，发布说明标注）。
- 安全与审计：更新包完整性校验（签名/哈希）；下载走 HTTPS；update feed 不泄露密钥；组件操作只写用户自身 agent 目录。
- 可用性与降级：任何更新失败/离线 → 静默降级（手动更新内联报错），旧版完全可用；无阻塞性错误。
- 可观测性：自更新/联动/预装/手动组件更新记录**结构化日志，字段=时间、触发来源（手动/预装/联动）、包名、旧版本、新版本、结果**；updater-state.json 同步维护 components 版本快照；写入 userData 日志便于排障。
- 兼容性：Windows 10/11 x64；per-user 安装免管理员；与既有 `~/.pi/agent` 数据兼容。
