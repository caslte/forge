# Skill 管理 PRD

> 状态：PRD 已确认（2026-09-22 用户「开工」批准）

## 1. 场景意图

### 1.1 业务背景与目标

forge 的 skill 生态目前是**只读**的：pi 自动发现并加载四个位置的 skill——全局 `<userData>/agent/skills/`（forge 生产 agentDir，未注入回退 `~/.pi/agent/skills/`）与 `~/.agents/skills/`（scope=user）、项目 `<project>/.pi/skills/` 与 `<project>/.agents/skills/`（scope=project，`.agents/skills` 还会从 cwd 向上遍历至 git 仓库根；以上均要求项目已信任，优先级 project-auto > user-auto，已在 pi 0.84.3 `core/package-manager.js` 源码验证）。forge 仅在斜杠命令浮窗（CV-S08）间接展示为 `/skill:<name>`。用户增删 skill 目前只能手工到文件系统操作，无感知、无校验、无入口。

本模块目标：在设置页提供 Skill 管理能力——**查看（全局+项目两级）、导入本地文件夹、按模板新建、删除**，操作结果自动被现有斜杠命令与 pi 运行链接 consume。

### 1.2 场景清单

| 场景 ID | 场景 | 业务价值 | 必须达成 | 明确不做 |
|---|---|---|---|---|
| SK-S01 | Skill 列表查看 | 一眼看清装了哪些 skill、来自哪级 | 展示名称、描述、来源（全局/项目两组，组内每条带实际根目录路径徽标，覆盖 pi 扫描的 4 个根）、所在路径；SKILL.md 缺失或 frontmatter 解析失败的非法 skill 以异常态展示（含诊断信息），不静默吞掉；同名跨根冲突按 pi 优先级（project-auto > user-auto）标注谁生效 | 不做 skill 内容在线预览/编辑 |
| SK-S02 | 导入本地文件夹 | 低成本复用他人 skill | 目录选择（原生对话框）→ 校验含合法 SKILL.md → 复制到目标作用域（全局或当前项目）；目标同名目录冲突时弹窗确认，同意后旧目录移入回收站再导入新的，不静默覆盖 | 不做 URL/GitHub/marketplace 在线安装（本期） |

### 1.3 边界与权限

- **不可接受方案**：fork/修改 pi SDK 的 loader 与 skills 加载逻辑；在 forge 内重造 skill 执行引擎（skill 执行始终归 pi）。
- **必须满足条件**：所有写操作（复制/创建/删除）的路径必须经 normalize 后校验落在对应 skills 根目录内（防路径穿越）；只作用于 skills 根的**直接子目录**；渲染进程不直接接触文件系统，全部经 IPC 由主进程执行。
- **角色与权限边界**：单用户本地应用；项目级 skill 操作仅面向当前打开的项目。

### 已采用的常规默认项

- Skill 目录规范：`<root>/<dir>/SKILL.md`，frontmatter 含 `name` / `description`；导入校验 SKILL.md 存在且 frontmatter 可解析，不通过则拒绝导入并给出原因。
- frontmatter `name` 与目录名不一致：不阻塞（以 pi 实际加载口径为准），列表以 loader 返回的 name 展示。
- 列表按来源分组两个 Tab 或分区（全局 / 项目），组内按名称排序；每项操作按钮：删除（全局与项目均有）、导入/新建时目标作用域二选一。
- 操作失败（权限、磁盘、解析）透传具体错误信息到 toast，不吞栈。
- 增删操作记主进程英文日志（可观测性沿用既有纪律）。

## 3. 详细设计

### 3.1 模块概述与边界

- 业务目标：设置页管理 pi 生态 skill：查看（全局+项目）、导入文件夹、模板新建、删除。
- 核心职责：skill 枚举（复用 DefaultResourceLoader，4 根归 2 组）、写操作（复制/创建/删除+回收站）、路径安全守卫、冲突确认交互。
- 核心业务对象：SkillEntry = name + description + source(scope) + rootPath + skillFilePath + valid/diagnostics + active(同名冲突是否生效方)；SkillScope = user | project。
- 涉及角色：单用户本地应用。
- 前置条件：pi 运行时可用（loader 已验证装配路径，沿用 slashCommandResources.ts 模式）；项目级操作要求已打开项目。
- 上下游与职责边界：上游=设置页 UI；下游=pi 文件系统约定（forge 只读写目录，不改 settings.json、不 reload 活跃会话）；斜杠命令链路（模块 03 CV-S08）为消费方，零改动自然反映。

### 3.2 核心流程与状态

```
列表：UI invoke skill/listSkills
  → desktop 构造 DefaultResourceLoader(cwd=projectPath??process.cwd(), agentDir)
  → getSkills()+diagnostics → 按 scope 归组 + 根路径标注 → 返回
导入：选目标 scope → 原生目录对话框 → 校验 SKILL.md → 同名冲突?
  → [冲突] 确认弹窗（旧目录将移入回收站）→ 同意 → trash(旧) → copy 新 → 刷新列表
  → [无冲突] copy → 刷新列表
删除：确认弹窗（绝对路径）→ shell.trashItem → 失败回退 rm -rf（仅限守卫内路径）→ 刷新
新建：表单(name/description/正文) → 校验 → mkdir + 写 SKILL.md → 刷新
```

### 3.3 功能点

#### 功能点：SK-F01 Skill 列表查看

- 目标：完整呈现 4 根 skill 及健康状态。
- 前置条件：boot 完成；项目级组要求已打开项目。
- 业务规则：两组展示（全局=user scope 两根、项目=当前项目两根），每条带根路径徽标；loader 口径与运行时一致（含 enabled/disabled、collision skip）；非法 skill 进异常态分组展示诊断；未打开项目时项目组空态提示。
- 业务数据：`skill/listSkills` 返回 `SkillEntry[]`。
- 交互与反馈：进入分区即加载，loading 态；刷新按钮重查。
- 权限边界：只读。
- 合法/非法状态流转：valid / invalid(诊断) / collision-loser(被 skip，标注"被同名覆盖")。
- 异常与边界：loader 抛错 → 空列表+错误 toast，不白屏；无项目信任 → 项目根不被 pi 扫描，列表如实为空并提示"项目未信任"。
- 数据一致性与幂等：查询无副作用。
- 跨模块影响：与 CV-S08 斜杠命令枚举共用 loader 装配函数，避免两处漂移。

#### 功能点：SK-F02 导入本地文件夹

- 目标：把含 SKILL.md 的目录复制进目标根。
- 前置条件：主进程可弹原生目录对话框。
- 业务规则：目标根固定（全局→`<agentDir>/skills`，生产 = `<userData>/agent/skills`，项目→`<project>/.agents/skills`）；校验源目录含可解析 SKILL.md，失败拒绝并给原因；同名冲突→确认弹窗，同意后旧目录移回收站再导新（用户 2026-09-22 拍板）；取消确认=放弃导入，旧目录不动。
- 业务数据：`skill/importSkill { scope, sourceDir? }`；sourceDir 由主进程对话框返回或 UI 传参（对话框在 desktop 层）。
- 交互与反馈：成功 toast+列表刷新；冲突确认弹窗展示将移入回收站的旧路径与新来源路径。
- 权限边界：写入仅限目标根直接子目录。
- 合法/非法状态流转：选择→校验→(冲突确认)→复制→完成；任一步取消/失败回到列表原状。
- 异常与边界：源=目标路径（自我复制）拒绝；复制中途失败清理半成品目录并报错；磁盘满/权限错误透传。
- 数据一致性与幂等：复制以临时目录+rename 原子落位，不留半个 skill。
- 跨模块影响：无（下次斜杠命令查询自然反映）。

#### 功能点：SK-F03 模板新建

- 目标：表单生成标准 SKILL.md。
- 前置条件：同上目标根规则。
- 业务规则：name 校验 `^[a-z0-9][a-z0-9-]*$`（目录安全）；description 必填；正文写入模板 `---\nname: "…"\ndescription: "…"\n---\n\n# …\n\n{正文}`；同名冲突同 F02 确认语义。
- 业务数据：`skill/createSkill { scope, name, description, body }`。
- 交互与反馈：表单校验即时提示；成功 toast+刷新。
- 权限边界：同 F02。
- 合法/非法状态流转：填写→校验→创建→完成。
- 异常与边界：正文含 frontmatter 分隔符不特殊处理（正文在第二个 `---` 后，pi 解析以文件首个 frontmatter 块为准——开发时以真实 loader 回读验证为准）；创建后立即用枚举回读确认。
- 数据一致性与幂等：目录已存在即冲突路径，不静默合并。
- 跨模块影响：无。

- 异常与边界：回收站与 rm 均失败→透传错误；只读目录提示。
- 数据一致性与幂等：重复删除第二次报"不存在"，不报成功。
- 跨模块影响：无。

- 目标：一次勾选并删除多个 skill 目录。

- 业务规则：头部「批量管理 Skill」按钮点击进入批量模式（按钮变「退出批量管理」，行内出现复选框、单个删除图标隐藏）；「批量删除 Skill (N)」仅 N≥1 可点；确认弹窗列出全部所选目录后逐条调 `skill/deleteSkill`（单条接口复用 containment 校验 + 回收站回退，后端零改动）；单条失败不中断，汇总上报（成功数 / 永久删除数 / 失败数）；全部成功自动退出批量模式，有失败则保留批量模式便于重试。
- 业务数据：无新 RPC（UI 循环调既有 `skill/deleteSkill`）。
- 交互与反馈：删除中按钮禁用防重入；成功 toast「已删除 N 个 skill」，部分回收站不可用追加永久删除说明；失败逐条错误 toast。
- 权限边界：同 F04（服务端逐条强制）。
- 合法/非法状态流转：进入批量模式→勾选→确认弹窗→逐条删除→（全成）自动退出 /（有败）留在批量模式。
- 异常与边界：退出批量模式即清空勾选；0 选中时批量删除按钮禁用；目录已被外部删除按单条失败计。
- 数据一致性与幂等：重复删除报"不存在"计为失败，不报成功。
- 跨模块影响：无。

### 3.4 页面承载

- 页面路径与访问权限：设置页新增「Skills」分区（紧邻「版本更新」分区）。
- 页面结构：顶部说明+生效提示 → 操作条（作用域切换 全局/项目、导入按钮、新建按钮、批量管理开关、刷新）→ 列表（名称、描述、根路径徽标、删除按钮；批量模式下为复选框）→ 异常态子列表（诊断文案，可折叠）。
- 操作入口、按钮和链接：导入（主进程目录对话框，支持多选）、新建（表单弹窗）、删除（确认弹窗）、批量管理 Skill（开关，进入后出现批量删除按钮与复选框）。
- 表单字段与业务校验：新建=name（正则即时校验+冲突检查）/description（必填）/正文（选填 textarea）。
- 弹窗、loading、成功/失败反馈：列表 loading 骨架；冲突/删除确认弹窗；toast 反馈。
- 失败时的上下文和数据保留：新建表单失败保留输入；导入失败保留作用域选择。

### 3.5 非功能要求

- 性能与容量：枚举单次 loader 构造（百 ms 级，与 CV-S08 同量级）；列表支持数百 skill 无虚拟化需求。
- 安全与审计：全部写路径 containment 复验；不触碰 skills 根以外任何文件；不改用户 settings.json/trust。
- 可用性与降级：loader 失败只影响列表不崩设置页；trashItem 不可用平台回退永久删除并明示。
- 可观测性：增删改主进程英文日志（操作、目标路径、结果）。
- 兼容性：Windows 主平台（回收站经 Shell API）；macOS/Linux 走 Electron 通用实现。
