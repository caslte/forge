## 1. 场景意图

### 1.1 业务背景与目标

会话内的对话编程是 forge 的核心交互：用户发送消息，pi `AgentSession` 处理并流式返回响应（可能含工具调用，工具执行展示见模块 04）。forge 负责消息的流式增量渲染（Markdown / 代码高亮 / Mermaid）与消息历史加载，让用户在会话中获得实时、富文本的编程对话体验。

### 1.3 边界与权限

- **不可接受方案**：渲染任意 HTML（XSS）；取消时丢弃已生成内容；流式卡顿/阻塞 UI；历史消息丢失或重复。（扩展 CV-S06）点击定位后被流式自动滚底冲走；浮窗渲染富文本引入 XSS 面。（扩展 CV-S08）插入的命令文本与 pi 识别所需原始串不一致（如插入美化名「Git Push」导致 pi 无法执行）；命令枚举失败导致输入框不可用。（扩展 CV-S11）把 todo 状态做持久化、跨会话重放或暴露给用户编辑；面板错位遮挡输入框；面板在空列表时残留占位。

- **必须满足条件**：消息 = pi session 消息（复用 pi 存储）；流式增量渲染；Markdown 安全渲染（白名单）；取消保留已生成内容。（扩展 CV-S06）时间线/浮窗均为纯文本展示（文本插值默认转义）；定位进入回看模式不被流式打断。（扩展 CV-S08）浮窗列表仅为展示美化，**插入文本恒为原始命令串**（如 `/skill:git-push ` ，尾随空格、光标在后便于续输参数）；命令枚举失败降级为空列表且不阻塞输入。

- **角色与权限边界**：单用户；无 per-tool 审批（跟 pi 一致）；消息内容信任由 pi 处理，forge 仅渲染。（扩展 CV-S08）命令枚举只读，不改变 pi 会话状态；命令执行沿用消息发送权限边界。

### 1.4 已确认业务决策

- 消息复用 pi session JSONL 存储，forge 不重造消息存储（对齐模块 02）。

- 流式响应：pi 事件经 forge-core 映射为 `CanonicalEvent`，经传输无关接口增量推送前端（桌面 IPC 事件 / headless SSE）。

- 富文本渲染复用 ai-coding 前端（marked / prismjs / mermaid）。

- 取消 = 停止 `AgentSession` 当前处理，保留已生成内容（跟 pi abort 语义一致）。

- （扩展 CV-S06）时间线与浮窗由**当前会话已加载的消息流**派生，零新增接口、零新增存储；仅作用于主会话消息流（子 agent 结果视图不渲染时间线，画布小窗后续迭代）。

- （扩展 CV-S06）交互参考 ZCode 客户端会话历史浮窗；用户裁定并入本模块主会话侧，不单独设模块。

- （扩展 CV-S08，用户裁定 2026-09-02）命令面板只列 **pi 生态自动发现命令**：扩展命令（`pi.registerCommand` 注册）+ skills（`skill:name`）+ prompt 模板，全量展示、自动发现；**pi TUI 内置命令（/model /compact /quit 等）一律不做 forge 侧映射、拦截与展示**（桌面已有等价 UI 或无桌面意义）。

- （扩展 CV-S08）命令选中后**原样经既有消息发送链路**发送，pi 运行时原生解析执行（扩展命令立即执行 / skill 展开 / 模板展开）；forge 不解析命令语义、不设命令注册表。

- （扩展 CV-S08）浮窗显示美化参考 codex：条目**不显示** **`/`** **与** **`skill:`** **前缀**；kebab-case 转 Title Case（`git-push` → `Git Push`）；skill 条目**加粗 + 品牌色**，扩展命令普通前景色，prompt 模板弱化色；条目副文本显示命令描述；列表为单一列表（不做分组区块），来源以条目标签区分。

- （扩展 CV-S08）选择方式：↑↓ 高亮导航、Enter/Tab/鼠标单击插入原始命令文本（含尾随空格）；Esc、输入框失焦、命令前缀被删空时关闭浮窗。

- （扩展 CV-S11，用户裁定 2026-09-10）面板位置固定在主会话输入框正上方；视觉规范复用 pi TUI 端 rpiv-todo 同款（标题计数 + 状态字符 + activeForm 括号 + 完成态删除线 + tree 前缀 `├─/└─`）；不自定义 chrome 文案与符号，差异点后续迭代讨论。
- （扩展 CV-S11）面板只读、不挂写接口；状态完全跟随 pi 运行时（即与 rpiv-todo TUI 端天然一致），forge 仅作为只读镜像，不存不存不落、不开跨会话回放、不允许手动增删改（v1.2 简化，后续按需开放）。
- （扩展 CV-S11）面板默认展开，折叠状态仅内存维护（按会话隔离，不写 localStorage、不跨会话同步）；不做快捷键折叠，交互入口 = 点击头部（点击头部任意位置切换折叠状态、chevron 仅作状态指示）。
- （扩展 CV-S11）折叠态与空快照 = 面板从 DOM 卸载（不留高度、不留占位、不显骨架），避免输入框错位与视觉噪声；子 agent 结果视图与画布小窗不承载面板（仅主会话承载）。

## 3. 详细设计

### 3.1 模块概述与边界

- **业务目标**：会话内对话编程，覆盖发送、流式响应、富文本渲染、取消、历史加载。

- **核心职责**：消息发送、流式接收与增量渲染、Markdown 安全渲染、取消、历史消息加载。

- **核心业务对象**：消息（Message）= pi session 消息（角色 user/assistant/tool，内容、时间）。

- **涉及角色**：单用户。

- **前置条件**：会话已创建（模块 02）；provider 已配置（模块 05，未配置则提示）。

- **上下游与职责边界**：

  - 上游：模块 02 会话管理（会话存在）。

  - 下游：模块 04 工具执行展示（工具消息卡片在对话区穿插）；pi（AgentSession、session 存储）。

  - 数据边界：消息存储归 pi；渲染状态归 forge 前端。

### 3.2 核心流程与状态

```
发送消息 -> AgentSession 处理 -> 流式响应(token 增量) -> 渲染 -> 完成
取消: 运行中 -> 停止处理 + 保留已生成 -> 空闲(可继续发新消息)
历史: 打开会话 -> 加载 pi session 消息 -> 渲染 -> 滚到最新
```

会话执行状态：`空闲` -> `运行中(流式)` -> `已完成` / `已取消` -> `空闲`。

### 3.3 功能点

#### 功能点：CV-S01 发送消息

- **目标**：用户向会话发送消息触发 AI 处理。

- **前置条件**：会话存在；provider 已配置。

- **业务规则**：消息非空才可发送；发送后进入流式响应；消息写入 pi session。

- **业务数据**：消息内容、角色 user、时间戳。

- **交互与反馈**：输入框输入 -> Enter 发送 -> 消息追加到对话区 -> 进入流式响应。provider 未配置时提示先配置而非崩溃。

- **权限边界**：无审批（跟 pi 一致）。

- **合法/非法状态流转**：空闲 -> 运行中（合法）；运行中再发送（CV-S09 起合法 = 入队，v1 的禁用方案被队列替代）。

- **异常与边界**：provider 未配置 -> 提示配置；发送失败 -> 提示，消息可重发。

- **数据一致性与幂等**：消息写 pi session；运行中重复发送经 CV-S09 入队（FIFO 不会重复）；入队失败（扩展命令不能排队）返 5000 且不影响在途轮次状态。

- **（扩展 CV-S09）队列状态机**：pi 内部 FIFO（session 层镜像 + agent 层队列双层）；`queue_update` 事件全量推送；派发时 pi 先移队再发 `message_start(role=user)`，适配器以「离队 + message_start(user)」确认派发并转发 user 气泡事件（直发路径不转发，本地已 push 无重复）；停止 = `clearQueue()`（双层清）-> `abort()`，对齐 pi TUI ESC。

- **（扩展 CV-S10）历史状态机**：cursor = -1（当前编辑）/ 0..n-1（历史索引，0 最新）；进入历史前暂存草稿，走过最新回填；浮窗（@/斜杠）打开时浮窗导航优先；切换会话若处于历史模式则清空残留回填文本。

- **跨模块影响**：触发模块 04 工具执行展示（若 AI 调工具）。

  - 消息流新增用户消息（含流式期间发送）后条目实时出现，与消息流同源，无独立刷新动作。

  - hover 条目停留 ≥300ms 弹出浮窗：显示该轮对话快照——该条用户消息（截断 120 字符）+ 其后最后一条助手回复（截断 200 字符），纯文本（按码点截断）；浮窗为快照，流式期间不实时刷新。移开条目/浮窗或按 Esc 立即关闭；停留不足 300ms 移开不弹、不发任何请求。

- **权限边界**：不适用（会话内只读派生视图，无权限变化、不触发资源加载）。

- **合法/非法状态流转**：浏览模式 ↔ 回看模式（点击定位进入，触底/点击提示退出，合法）；浮窗 关闭↔展示（合法）。

- **异常与边界**：用户消息无助手回复（等待中/出错）→ 浮窗显示提问 + 状态提示；超长会话（200 条用户消息）时间线内部滚动不挤占消息区；定位目标消息被工具组折叠不影响（定位到用户消息本身，永远可见）。

- **数据一致性与幂等**：时间线为消息流纯派生，切换会话随消息流重建；重复点击同一条目等价一次定位。

- **跨模块影响**：只读消费本模块消息流；不改变模块 02 切换语义与模块 04 工具卡片渲染。

#### 功能点：CV-S07 上下文压缩

- **目标**：长对话接近上下文上限时释放空间，且压缩过程对用户可见、可预期。

- **前置条件**：会话已激活（至少发过一条消息）；provider 已配置。

- **业务规则**：

  - 压缩能力由运行时（pi `AgentSession.compact()`）提供，forge 不自定义阈值与摘要策略。

  - **手动压缩**：输入框上下文用量区提供「压缩」入口，调用 `conversation/compact`。

  - **自动压缩**：运行时按阈值/上下文溢出自动触发，forge 侧无 RPC 入口，统一经
    `conversation.compacted` 事件通知 UI（`reason: auto`）。

  - **流式保护**：streaming 期间禁用压缩入口——运行时压缩会先 `abort` 当前轮，
    若允许点击会静默截断正在生成的回答。

  - **历史口径（2026-09-26 口径修正）**：压缩**只替换喂给模型的上下文**，不动
    用户看到的 transcript。历史加载读 pi 会话的**全量分支**（`getBranch()`，
    叶子→根），**不用** `buildContextEntries()`（后者是已应用压缩的上下文视图，
    会把压缩点之前的条目换成摘要）；压缩点位置渲染一条「上下文已压缩」分隔条 +
    可展开摘要。原因：用户反馈「压缩完了之后之前的历史消息没了」——彼时旧消息连同
    摘要一起消失（旧消息被压缩视图剔除、compaction 条目又被当作非消息条目跳过）。

- **业务数据**：压缩前后 token 数、压缩摘要、触发来源（manual / auto）。

- **交互与反馈**：

  - 手动压缩成功：入口附近显示「压缩完成：{before} → {after} tokens」，4s 后消失；

  - 手动压缩失败：显示失败原因（如「Nothing to compact」「会话未激活」）；

  - 自动压缩完成：消息区顶部出现提示条「上下文已自动压缩，历史已更新」，5s 后消失，
    并重新拉取会话历史（重拉是为了拿到新产生的压缩标记，不是因为历史被删——
    见「历史口径」：压缩点之前的对话始终保留）；

  - 自动压缩失败：走 `conversation.error` 上报，绝不静默。

- **权限边界**：无审批（跟 pi 一致）。

- **合法/非法状态流转**：空闲/已完成 -> 压缩中 -> 完成（合法）；streaming 期间压缩（非法，禁用入口）。

- **异常与边界**：压缩后运行时可能暂无法给出可信用量（返回 `tokens: null`），
  UI 显示「未知」而非 0，避免用户误判压缩未生效；
  重启后仅加载历史（无 lease）的会话，用量从磁盘估算（最后有效 assistant 用量

  - 尾部估算，与 pi 同规则，contextWindow 取会话模型），发出首条消息后回落为
    运行时实时读数。

- **数据一致性与幂等**：压缩失败不破坏会话历史；重复点击在压缩中与流式期间被禁用。

- **跨模块影响**：模块 05 模型 provider 提供 contextWindow（用量条上限与压缩阈值来源）。

#### 功能点：CV-S08 斜杠命令（扩展）

- **目标**：输入框支持 pi 生态斜杠命令的可发现与引用——行首输入 `/` 弹出命令浮窗（扩展命令 / skills / prompt 模板），浏览、过滤、选择插入，命令经既有消息发送链路原样交给 pi 原生识别执行。
- **前置条件**：输入框可用（非 streaming）；命令清单已拉取（草稿态轻量查询 skills/模板；会话激活后含扩展命令的上报补全）。
- **业务规则**：
  - **命令数据源**（三类，全量自动发现，TD-CV-07）：
    - 扩展命令：forge-extensions 承载的命令上报扩展在会话启动时调用运行时命令枚举能力（覆盖扩展命令 + skills + prompt 模板三类）经事件总线上报，forge 按会话缓存；
    - skills：命令名带 `skill:` 前缀（如 `skill:git-push`）；
    - prompt 模板：模板名即命令名。
  - **草稿态降级**（TD-CV-08）：未发首条消息（无运行时会话）时以轻量资源查询直取 skills 与 prompt 模板，扩展命令不可见；会话激活（首条消息发出、扩展上报到达）后补全三类。
  - **触发**：光标所在行行首为 `/`（该行第一个字符）时浮窗打开；过滤串 = 该行 `/` 之后至光标的文本；命令已确定（该行出现空格）后浮窗关闭。
  - **过滤**：包含匹配（原始命令名或描述、大小写不敏感；用户裁定 2026-09-03 由前缀匹配放宽），保持清单原序不做相关度排序；无匹配时浮窗显示「无匹配命令」而非隐藏；清单为空（枚举失败或确无命令）时显示「无可用命令」。
  - **展示美化**（codex 风格，仅浮窗内）：条目不显示 `/` 与 `skill:` 前缀；命令名 kebab-case 转 Title Case（`git-push` → `Git Push`）；skill 条目**加粗 + 品牌色**，扩展命令普通前景色，prompt 模板弱化色；每条目副文本显示命令描述；单一列表（不做分组区块），来源以条目标签区分（技能 / 命令 / 模板）。
  - **选择与插入**：↑↓ 在可视列表内循环导航高亮；Enter / Tab / 鼠标单击选中——把当前行的命令前缀文本（含 `/` 起至光标）替换为**原始命令串 + 尾随空格**（如 `/skill:git-push `），光标落在空格后便于续输参数；插入后浮窗关闭。浮窗打开期间 Enter / Tab 被浮窗消费（选择命令），不触发消息发送与焦点移动。
  - **关闭**：Esc、输入框失焦、命令前缀被删空（行首 `/` 删除）、行内出现空格、完成选择插入；关闭后 Enter 恢复发送语义。
  - **发送**：选中或手打的命令文本经 CV-S01 既有发送链路原样发送，pi 运行时原生解析执行（扩展命令立即执行 / skill 展开为 skill 块 / 模板展开为模板内容，TD-CV-09）；forge 不解析命令语义、不设命令注册表、不做 TUI 内置命令映射。
  - **消息气泡显示**（用户验收修正，2026-09-02；多技能引用扩展 2026-09-03）：发送内容仍为原始串不变；气泡展示层把命令段渲染为浮窗同款美化（`Gen Doc All` + 来源标签，skill 加粗品牌色），剩余正文照常展示；命令段与正文同行内联穿插。正文内全部 `/skill:name` 引用逐个美化（`splitSkillRefs` 切段，纯样式性——pi 仅展开消息开头第一个命令，其余引用是否执行由 pi/模型判断，美化不代表执行）。识别两种形态：发送原始串（行首 `/` + 无空白 token）与 pi 展开持久化形态（`<skill name=...>指令文档</skill>` + 尾部用户正文，重载历史时指令文档收起不展示、只留用户正文）；非命令消息不误伤。
  - **streaming 期间**：输入框本已禁用，浮窗不可触发。
- **业务数据**：命令清单（命令名、描述、来源类型），会话级内存缓存，无持久化；同一会话内首次触发浮窗时拉取一次，切换会话失效重拉（运行期新装 skill/扩展不热刷新，重开会话生效）。
- **交互与反馈**：浮窗自输入框向上弹出（对齐既有浮窗菜单样式），出现过渡 ≤150ms；浮窗宽度不超过输入框宽度（长描述/长命令名超出省略号截断）；命令数量多时浮窗内部滚动；单/多窗口输入框行为一致。
- **权限边界**：命令枚举只读、不改变 pi 会话状态；命令执行沿用消息发送权限边界（无审批，跟 pi 一致）。
- **合法/非法状态流转**：浮窗 关闭 ↔ 打开 ↔ 高亮导航（合法）；插入后浮窗关闭（合法）；streaming 期间触发浮窗（非法，输入禁用不可达）。
- **异常与边界**：命令枚举失败 → 降级为空清单 +「无可用命令」提示，输入与发送不受阻塞（用户仍可手打完整命令）；描述缺失的命令 → 副文本留空不报错；超长命令名/描述 → 单行截断 + 原生 title 提示。
- **数据一致性与幂等**：同一会话重复触发浮窗不重复拉取；插入文本恒为原始命令串（美化名不进入输入框）；多次选择同一命令结果一致。
- **跨模块影响**：forge-extensions 承载首个真实 pi 扩展（架构层面启用，无业务耦合）；无新增持久化。

#### 功能点：CV-S11 Todo 面板（扩展，v1.2）

- **目标**：在主会话的输入框上方渲染只读 todo 面板，让用户随时看到 agent 当前在做什么、还剩什么，不心流切换到 CLI 端查看（与 pi TUI 端 rpiv-todo 面板同款视觉）。

  - **过滤与展示**：从快照剔除 `status === 'deleted'` 的墓碑（与 rpiv-todo 同款），剩余按 (completed, in_progress, pending) 三段顺序、组内按 `id` 升序渲染；任务行渲染四要素：状态字符（`○` pending 空心点 dim / `●` in_progress 呼吸点 warning / `✓` completed success），subject（pending 正常文字色；in_progress 灰色文字 muted；completed/deleted 灰色 + 删除线），in_progress 且有 `activeForm` 时同行括号展示，blockedBy 装饰留后续（v1.2 不展示，避免与 rpiv-todo 视觉分叉引入新符号）。

  - **不**做：手动增删改、拖拽排序、依赖图编辑、跨会话历史回放（TD-CV-11）、持久化、快捷键。
- **业务数据**：`todoSnapshot: { tasks: Array<{ id, subject, status, activeForm?, blockedBy? }>, nextId: number } | null`，纯组件内存。
- **交互与反馈**：默认展开；折叠态仅渲染标题行 + chevron（不展开任务列表）；折叠/展开时任务列表高度 + 透明度过渡动画（≤200ms）；面板为 opencode 风格浮窗卡片（上/左/右边框 + 顶部圆角与输入框同款，下边沿无 border、底部塞进输入框背后形成延伸一体感）；任务列表可视区固定 3 行高度，超出内部滚动（4px 细滚动条）；任务行过长按码点截断 + 省略号（中文按 CJK 宽度 2 计，与对话气泡同款）。**长任务列表可见性保证**（AC-CV-042）：有 in_progress 时保证其落在 3 行可视窗口内（不强求顶部），用户不用手动滚动就能看到当前在做什么；无 in_progress（全部完成）时滚到最后一行让用户看到最终状态。触发时机：初次挂载 / 折叠→展开 / 布局变化；函数内部检查目标行已可视则 no-op，不抢用户手动滚动位置。空快照 / 卸载时不显示过渡动画（避免视觉噪声）。
- **权限边界**：面板只读，不向 pi 发送任何写请求；折叠状态仅本地 UI 状态，不跨进程、不持久化。
- **合法/非法状态流转**：折叠 ↔ 展开（点击头部切换，合法）；可见 task 数从 N>0 → 0（自动卸载，合法）；可见 task 数从 0 → N>0（自动挂载，默认展开）；会话切换（旧快照保留在内存 Map → 切回时还原，按 sessionId 隔离，合法）；**会话进入终态（status ∈ {done, idle, canceled, error}）→ 对当前会话快照里的 in_progress 任务兑底标为 completed**（agent 忘了调 todo 工具收尾时免面板永远挂呼吸点；兑底后走“全部完成 → 折叠 → 隐藏”路径；快照无 in_progress 时原引用返回）。
- **异常与边界**：`details` 缺失或结构非法（不是 `{ tasks: [] }`）→ 静默忽略当次完成事件，不污染当前快照；subject 为空 → 渲染占位「（无标题）」避免空行；activeForm 为空 → 不渲染括号；任务数超大（>50）→ 仅渲染前 50 行 + 「+N more」收口（避免长面板撑爆布局，与 rpiv-todo 同款降级）；in_progress 任务被 `clear` 动作清空后视为空快照卸载。
- **数据一致性与幂等**：快照 = 最近一次成功 `tool.completed(todo)` 的 `details` 全量复制；多次重复同快照原地替换结果一致；流式过程中 partial 状态不消费（仅 `status === 'completed'` 的 `tool.completed` 事件参与更新）。
- **跨模块影响**：消费模块 04 扩展的 `tool.completed.result.details` 字段（TE-S05）；不修改消息流、不影响模块 02 会话切换语义、不影响模块 04 工具卡片渲染（todo 工具自身的工具卡仍按通用规则展示）；与 rpiv-todo TUI 面板共享同一数据源，状态天然一致。

#### 功能点：CV-S12 ask_user_question 内嵌问卷（扩展，v3.65）

> 说明：本功能承接 v3.64 的「插件上架」阶段，改为**forge 自建内置扩展 + 自有 UI 渲染**（Path 2）。
> 契约见 `docs/plan/ask-user-question-contract.md`（编码唯一依据），实施计划见 `docs/plan/ask-user-question-extension.md`。

- **目标**：模型在需求不明确时主动向用户提出结构化问题（1–4 题 × 2–4 选项，可多选、可带 markdown 预览），forge 在输入框上方以内嵌面板承载交互，替代 CLI 侧的 TUI 左右分栏；用户作答后答案经原路回填给模型继续推理。
- **前置条件**：主会话已激活；forge 内置扩展 `ask_user_question` 已注册（随 forge 版本走，不依赖 agent 目录预装）；模型判定需要澄清并调用该工具。用户环境若装有同名 rpiv 插件，由 `extensionsOverride` 在内存中屏蔽（不修改用户 `settings.json`）。
- **业务规则**：
  - **协议分层**（TD-CV-12）：工具注册用 pi 官方 `registerTool` SDK；`questions[]` 入参与 `details` 出参照抄 rpiv 私有约定（本地固化，不跟随上游）；传输通道（事件名 / RPC 方法 / `requestId` / 超时）为 forge 自有设计。
  - **投递**：扩展在 `execute` 内投递 `ask-user:request`（`{ requestId, questions, timeoutMs }`）到**该会话私有**的扩展事件总线 → 适配器按会话订阅并补齐必需 `sessionId` → 上抛 `conversation.askUserQuestionRequested`（已登记 `FORGE_EVENTS` 白名单）→ 渲染进程各窗格按 `sessionId` 认领。
  - **回填**：`askUserQuestion/reply` RPC（`{ sessionId, requestId, answers, cancelled, globalNote? }`）→ 适配器 `replyAskUserQuestion` 经该会话总线 emit `ask-user:reply:{requestId}` → 扩展侧 await 的 Promise 兑现 → 工具返回 `{ content:[{type:'text',text:envelope}], details }`。
  - **超时双阈值**：`DEFAULT_ASK_USER_TIMEOUT_MS = 600s`（10 分钟）随请求下发给面板驱动倒计时；面板**归零时主动回填**「已答部分 + `cancelled:true`」；扩展侧实际等待 `600s + ASK_USER_REPLY_GRACE_MS(1.5s)` 作为安全网。错开 1.5s 是为避免「扩展先超时 → 已答部分丢失」的竞态。
  - **preview 不回流**：`details.answers[].preview` 照常填充供 UI 展示，但模型侧 envelope **不含** `selected preview:` 段（rpiv 因 CLI 无面板被迫回流；forge 有真面板，省 token）。
  - **推荐标记双通道**：模型可能按新约定置 `options[].recommended = true`，也可能沿用旧习惯在 label 尾部加 `(Recommended)`。UI 两条通道都识别；识别到后缀时**仅显示层**剥离，回填给模型的 label 保持原始值。
  - **校验**：`validateQuestionnaire` 6 条规则（无题目 / 超 4 题 / 题干重复 / 选项为空 / 保留标签 / 选项标签重复）在扩展侧拦截，失败直接返回 `cancelled:true + error`，不投递面板。
  - **不**做：问卷历史回放、持久化、跨会话共享、把 preview 写回模型上下文。
- **业务数据**：会话级内存态，由 `useSessionConversation` 持有的状态仓 `createAskQuestionStore`（`composables/askQuestionStore.ts`）承载 —— 四张按 `sessionId` 索引的表：`requests`（进行中的请求）、`deadlines`（倒计时**绝对截止时刻**）、`answeredStates`（最近一次已答摘要）、`questionSets`（最近一次题目，供摘要回显「已答 n/N」）。⚠️ 四张表**必须**为 `reactive`：面板常驻挂载（`v-if="!showResultView"`，首屏尚无问卷就已渲染），`deadline` computed 会在首屏求值并**缓存空值**，普通 Map 的后续写入不产生依赖变更 → computed 永不重算 → 倒计时恒显示 0（真机出现过；已由 `test/askQuestionStore.test.ts` 两条回归锁用例钉住）。无持久化，APP 退出随进程消失。
- **交互与反馈**：面板为 opencode 风格浮窗卡片（与 TodoPanel 同款：上/左/右边框 + 顶部圆角、下边沿无 border、底部塞进输入框背后形成延伸一体感），置于输入框正上方，不遮挡消息流。多题时顶部 N+1 tab（末位「备注」），已作答 tab 圆点转 success 色；单选点选、多选 checkbox；任一选项带 preview 时切左右分栏（左选项列表 / 右 markdown 预览，hover 或选中项驱动，**面板高度固定不随 preview 长短变形**，**预览列刻意窄于选项列 = 1.4 : 1** —— 分栏态下选项描述已隐藏，左列不需要一半宽度；宽度比例由单条 `grid-template-columns` 控制）；**预览内 markdown 列表的黑点必须落在框内**（全局 `* { padding:0 }` reset 会清掉 `ul/ol` 的默认内边距，而 `list-style-position` 仍是 `outside`，黑点会被推到内容盒外、露在圆角框外 —— 必须显式把 `padding-left` 还给列表）；**「✎ 自己答」为选项列表末位的一行选项**（单选渲染 radio、多选渲染 checkbox），选中才在其下方整宽展开输入框；**单选下与普通选项互斥**（选普通选项即撤销该行并清空文本），**多选下与普通选项并列**（可同时选中、互不取消；收起输入框不丢文本；提交时文本并入 `selected` 末位，不另起 `kind='custom'` 条目）；**操作条整体位于标题行**（标题与「等待回答」徽标之间，依次为「已答 n/N」「上一题」「下一题」「取消」「提交答案」，点按钮不触发头部折叠），「提交答案」**仅在末步（最后一题之后的备注 tab）出现**；**单选作答后自动前进到下一步**（多选、点「自己答」、末步不前进），「上一题 / 下一题」供手动回看；默认展开、可点击头部折叠；头部右侧显示「等待回答 · {剩余}s」倒计时徽标。**「提交答案」在 payload 为空时禁用**（含「只填了备注、一题未选」）—— 空 payload 落到扩展侧会变成与「取消」完全相同的 `DECLINE` 信号，禁用后产出该信号的唯一入口就是显式点「取消」。**作答后自动收尾（答完即关）**：摘要（「已答 n/N · 答案摘要 · 备注」）只亮约 1.5s，随即面板折叠关闭并卸载 —— 答案已回填给模型，消息流里的工具卡片已留痕，无需再占着输入框上方；收起后该轮摘要不再出现（含迟到的 `tool.completed` 权威摘要，也不会因切走再切回而复活）。**唯一例外**：`deliveryFailed`（用户点了提交、答案却没送达扩展侧）时**保留**摘要可见，否则答案静默丢失、模型只能等到超时拿 `DECLINE`。注意该标记必须**显式传递**（不能靠 `cancelled && answers 非空` 推断 —— 超时归零时已答部分同样非空，而那条路径答案**已经**回填成功，误判会留下一张永不收起的过期卡片），且要**活过权威 `details` 覆盖**（`details` 里没有这个本地判定）。子 agent 结果视图激活时不渲染（仅主会话承载）。
- **权限边界**：面板只读渲染 + 本地作答，不向模型注入额外指令；作答内容经校验后回填；取消不产生任何模型可见的副作用（统一 `DECLINE_MESSAGE`）。
- **合法/非法状态流转**：无问卷 ↔ 交互态（请求到达 / tool.completed 收尾，合法）；交互态 → 已答折叠摘要（提交 / 取消 / 倒计时归零，合法）；已答摘要 → 卸载（新一轮问卷到达、用户发新消息、会话切换，合法）；会话删除 → 退订 channel，迟到请求不再上抛（合法）。
- **异常与边界**：请求载荷畸形（缺 `requestId` / `questions` 空或非数组 / `timeoutMs` 非正数）→ 适配器静默忽略，不投递半成品问卷；`details` 结构非法或含 `error`（校验阶段被拒）或无题目上下文 → 不渲染已答摘要；`delivered=false`（会话已删 / 无 lease / 请求已超时收敛）→ 摘要**据实标「已取消」**（模型此时收到 `DECLINE`），不显示并不存在的成功；越界选项下标 / 空草稿一律跳过不抛错。
- **数据一致性与幂等**：提交用 `settled` 标志防「倒计时归零回填」与「用户点击提交」竞态重复上报；同一请求重复回填第二次 emit 落空（扩展侧 Promise 已兑现）；已答摘要以 `tool.completed.details` 为权威，提交时的乐观摘要会被覆盖。
- **跨模块影响**：新增 ForgeEvent `conversation.askUserQuestionRequested`（`FORGE_EVENTS` 白名单）+ ForgeMethod `askUserQuestion/reply`（模块 04 IPC 契约）；`RECOMMENDED_PLUGINS` 移除 `@juicesharp/rpiv-ask-user-question`（11 → 10，模块 07 清单同步）；不修改消息流、不影响会话切换语义。

#### 功能点：CV-S13 选区复制浮窗（扩展，v3.88）

> 形态经 `prototypes/selection-copy-demo.html` 定稿（2026-09-29 用户拍板变体 B「tooltip 反色」）；参考图里的「添加到任务 / 在侧边任务中提问」被用户砍掉，只保留复制。

- **目标**：用户在消息气泡内拖选文字、松开鼠标后，在选区上方浮现一个「复制文本」小浮窗，一键复制选区内容——不用移到 footer 找整条消息的复制按钮。
- **前置条件**：无（纯渲染层本地行为，`main.ts` 引入 `selectionPopover.ts` 全局单例即生效，与 tooltip.ts 同款挂载模式）。
- **业务规则**：
  - **触发范围**：仅当选区锚点（`Selection.anchorNode`）落在 `.msg`（消息卡片根元素）内才弹出；侧栏、设置页、终端（xterm 有自己的 Ctrl+C/右键复制）、画布卡片（iframe 事件不回传）一律不触发。空选区/纯空白选区不弹。
  - **只复制选区文本**：不做「添加到任务」「在侧边任务中提问」等衍生动作（用户裁定）。
  - **复制后**：按钮翻「已复制」打勾态 1.4s → 浮窗收起并清空选区（与 footer 复制按钮的反馈时长同款）。
  - **零持久化零后端**：不落任何状态，不动消息流、不动 footer 既有复制按钮。
- **交互与反馈**：
  - 释放鼠标（mouseup，含双击划词）后弹出；上方放不下（贴近视口顶缘）翻到选区下方；水平居中于选区并夹紧在视口内（GAP 8px / EDGE 8px，与全局 tooltip 同款定位语言，fixed + transform 免疫滚动容器偏移）。
  - 样式 = 全局 tooltip 反色同款（`--foreground` 底 / `--background` 字）+ `--shadow-md` + `--radius-lg`，图标复用 footer 复制按钮的 SVG（复制双框 → 打勾）；z-index 9998 压在 tooltip（99999）之下。
  - 收起时机：任意滚动（capture 阶段，含消息流内部滚动）/ 在浮窗外重新按下鼠标 / Escape（同时清空选区）/ 复制反馈结束。
  - 文案走 i18n（`chat.copySelection` 中英双语；「已复制」复用 `chat.copied`），浮窗常驻期间切语言即时跟随。
- **权限边界**：只读剪贴板写入（`navigator.clipboard.writeText`，失败回退 `execCommand('copy')`，与设置页复制日志同款兜底）；不新增 IPC、不触碰主进程。
- **异常与边界**：选区塌陷/零尺寸矩形 → 不弹；anchorNode 为文本节点时取其 parentElement 判定归属；跨多条消息的选区按锚点所在消息判定（复制的是全部选中文本）。
- **跨模块影响**：无。与用户气泡「点开完整消息」既有守卫（拖选不算点击）互补不冲突。

### 3.5 非功能要求

- **性能与容量**：流式 token 端到端延迟 < 100ms；Markdown 渲染 < 50ms/消息；Mermaid 渲染 < 500ms/图；消息列表滚动 60fps。（扩展 CV-S06）时间线 200 条用户消息内渲染与滚动无明显掉帧；浮窗缓存命中即显（≤50ms，派生自本地内存）、出现/消失过渡 ≤150ms；派生计算（时间线重建）在消息流变更后 ≤50ms。（扩展 CV-S08）命令清单拉取（会话首次触发）< 500ms，缓存命中后浮窗打开 ≤150ms 过渡；100 条命令内浮窗滚动流畅；美化名转换与模糊过滤为纯前端计算、无请求。（扩展 CV-S11）面板更新（`tool.completed(todo)` 到达）至 React/Vue commit < 50ms；50 条任务渲染 < 16ms（一帧）；展开/折叠过渡 ≤ 200ms；会话切换 0 额外请求（清空快照，无网络）。

- **安全与审计**：白名单渲染防 XSS；无 per-tool 审批。（扩展 CV-S08）命令浮窗文本插值默认转义（命令名/描述均纯文本，无 v-html）。（扩展 CV-S11）subject / activeForm 文本插值默认转义（不拼 HTML，无 v-html）。

- **可用性与降级**：流式中断不丢内容；渲染错误不崩溃；代码语言不支持降级纯文本。（扩展 CV-S08）枚举失败降级空清单不阻塞输入；草稿态扩展命令不可见为可接受降级（会话激活补全）。（扩展 CV-S11）details 缺失/结构非法静默忽略；超 50 行任务降级「+N more」；子 agent 结果视图与画布小窗不承载面板（仅主会话）。

- **可观测性**：消息发送/取消/流式中断事件记日志。

- **兼容性**：渲染组件复用 ai-coding 前端。
