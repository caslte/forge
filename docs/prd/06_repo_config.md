# 模块六：仓库配置

## 模块概述

### 业务目标
管理本地 Git 仓库配置，为任务执行和对话提供工作目录上下文。

### 核心职责
- 仓库 URL 配置
- 本地仓库路径管理
- 仓库克隆与更新
- 工作目录隔离

### 涉及角色
- 开发者（配置仓库）
- 系统（任务执行时使用）

### 核心业务对象
- **仓库配置（RepoConfig）** - 仓库的 URL 和本地路径映射

### 前置条件
- 用户有可用的 Git 仓库

---

## 模块边界

### 上游模块
| 模块 | 输入 |
|------|------|
| 无 | 仓库配置为系统基础数据 |

### 下游模块
| 模块 | 输出 |
|------|------|
| 任务执行 | 提供工作目录 |
| 对话功能 | 提供仓库上下文 |

### 数据边界
- 一个工作空间可以有多个仓库配置
- 仓库配置存储在 workspace.repos JSONB 字段

### 职责边界
- 本模块不负责 Git 操作的具体执行（由 Claude Code CLI 处理）
- 本模块不负责仓库权限管理

---

## 核心流程与状态

### 仓库配置流程

```
┌─────────────────────────────────────────────────────────────────┐
│  用户配置仓库                                                    │
│       │                                                         │
│       ├── 添加仓库 URL                                          │
│       ├── 配置本地路径（可选，默认从 URL 推断）                   │
│       └── 保存到 workspace.repos                               │
│       │                                                         │
│       ▼                                                         │
│  任务执行时                                                      │
│       │                                                         │
│       ├── Daemon 获取仓库配置                                    │
│       ├── 检查本地路径是否存在                                   │
│       │     │                                                   │
│       │     ├── 存在 → 使用现有仓库                              │
│       │     └── 不存在 → 克隆仓库                                │
│       │                                                         │
│       └── 设置环境变量                                           │
│             │                                                   │
│             ├── MULTICA_WORKSPACE_ID                            │
│             └── MULTICA_TOKEN (如有认证)                        │
└─────────────────────────────────────────────────────────────────┘
```

### 仓库状态

| 状态 | 说明 |
|------|------|
| active | 正常，可使用 |
| cloning | 正在克隆 |
| error | 异常（克隆失败/路径不存在） |

## 功能点

### 功能 1：添加仓库

**功能目标/解决的问题**
用户需要添加 Git 仓库供任务执行使用。

**前置条件**
- 用户有可访问的 Git 仓库 URL

**业务规则**
- 仓库 URL 为必填项，必须是有效的 Git URL
- 本地路径为选填，不填则自动推断
- 支持 GitHub/GitLab/BitBucket 等标准 Git 服务
- 支持本地路径（file://）

**交互流程**
1. 用户点击「添加仓库」按钮
2. 系统弹出添加弹窗
3. 用户填写仓库 URL
4. 用户填写本地路径（可选）
5. 系统验证 URL 格式
6. 保存配置

**异常与边界**
- URL 无效：提示「无效的 Git URL」
- URL 重复：提示「该仓库已配置」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 添加成功 | E2E | 填写正确 URL 并保存 | - |
| URL 必填 | E2E | URL 为空时保存 | - |
| URL 格式验证 | 单元测试 | 非 Git URL | http://... |
| 路径重复 | E2E | 添加已存在的本地路径 | - |

---

### 功能 2：编辑仓库

**功能目标/解决的问题**
用户需要修改仓库配置。

**前置条件**
- 仓库配置存在

**业务规则**
- URL 和本地路径均可修改
- 修改后不影响已存在的工作目录

**交互流程**
1. 用户点击仓库的「编辑」按钮
2. 系统弹出编辑弹窗
3. 用户修改配置
4. 保存修改

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 编辑成功 | E2E | 修改配置并保存 | - |

---

### 功能 3：删除仓库

**功能目标/解决的问题**
用户需要移除不需要的仓库配置。

**前置条件**
- 仓库配置存在

**业务规则**
- 删除配置不删除本地仓库文件
- 有正在执行的任务使用该仓库时不可删除

**交互流程**
1. 用户点击仓库的「删除」按钮
2. 系统弹出确认对话框
3. 用户确认删除
4. 系统删除配置

**异常与边界**
- 任务使用中：提示「该仓库有任务正在执行」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 删除成功 | E2E | 确认删除 | 无任务使用 |
| 任务使用中不可删除 | E2E | 尝试删除有执行中任务的仓库 | in_progress |

---

### 功能 4：仓库克隆

**功能目标/解决的问题**
任务执行时需要准备仓库工作目录。

**前置条件**
- 仓库配置存在
- 仓库 URL 可访问

**业务规则**
- 只有在本地路径不存在时才克隆
- 克隆使用 `git clone --depth 1` 浅克隆
- 支持 HTTPS/SSH 认证（通过环境变量或 Credential Helper）

**交互流程**
1. 任务执行模块获取仓库配置
2. 检查本地路径是否存在
3. 不存在则执行 git clone
4. 返回工作目录路径

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 首次克隆 | 单元测试 | 本地路径不存在时 | - |
| 已有仓库 | 单元测试 | 本地路径存在时跳过克隆 | - |
| SSH 认证 | 单元测试 | SSH URL + 配置的 SSH key | - |
| HTTPS 认证 | 单元测试 | 私有仓库 + Token | - |

---

### 功能 5：仓库拉取

**功能目标/解决的问题**
保持仓库为最新状态。

**前置条件**
- 本地仓库存在
- 远程仓库可访问

**业务规则**
- 使用 `git pull --rebase` 保持分支整洁
- 只在必要时拉取（检查远程更新）

**交互流程**
1. 检查本地仓库是否存在
2. 检查是否有远程更新
3. 执行 git pull

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 拉取成功 | 单元测试 | 有远程更新时 | - |
| 无更新 | 单元测试 | 已是最新 | - |
| 冲突处理 | 单元测试 | 拉取冲突 | - |

## 数据库设计

### 仓库存储

仓库配置存储在 workspace 表的 repos JSONB 字段中：

```json
{
  "repos": [
    {
      "id": "repo-uuid",
      "url": "https://github.com/user/repo.git",
      "local_path": "~/projects/myrepo",
      "branch": "main",
      "status": "active"
    }
  ]
}
```

### JSONB 字段结构

| 字段 | 类型 | 说明 |
|------|------|------|
| id | UUID | 仓库 ID |
| url | TEXT | Git 仓库 URL |
| local_path | TEXT | 本地路径 |
| branch | TEXT | 默认分支 |
| status | TEXT | 状态 |

## 技术实现参考（Multica）

### 仓库信息传递

仓库配置通过 workspace.repos JSONB 存储，Daemon 获取后设置环境变量：

```go
// server/internal/daemon/task.go
func (d *Daemon) prepareTask(task *Task) error {
    // 获取工作空间仓库配置
    repos := task.Workspace.Repos

    for _, repo := range repos {
        // 检查本地路径
        localPath := expandHome(repo.LocalPath)
        if _, err := os.Stat(localPath); os.IsNotExist(err) {
            // 克隆仓库
            if err := d.cloneRepo(repo.URL, localPath, repo.Branch); err != nil {
                return err
            }
        }
    }

    // 设置环境变量
    env := map[string]string{
        "MULTICA_WORKSPACE_ID": task.Workspace.ID.String(),
        "MULTICA_TOKEN":        d.config.DaemonToken, // 用于认证
    }

    return nil
}
```

### Git 克隆

```go
func cloneRepo(url, path, branch string) error {
    cmd := exec.Command("git", "clone", "--depth", "1", "--branch", branch, url, path)
    return cmd.Run()
}
```

### 工作目录隔离

每个任务在独立的工作目录执行：

```
~/multica_workspaces/{workspace_id}/{task_id}/
├── .claude/
│   └── skills/
│       └── ...
├── repo1/          # 仓库文件
│   └── ...
└── repo2/
    └── ...
```
