# 模块一：任务管理

## 模块概述

### 业务目标
管理开发工作单元，支持创建、编辑、删除任务，设置状态和优先级，并将任务分配给 AI 助手执行。

### 核心职责
- 任务的完整生命周期管理
- 任务状态流转控制
- 任务优先级管理
- 任务与助手的关联
- 任务依赖关系管理（任务编排雏形）

### 涉及角色
- 开发者（创建、编辑、指派任务）

### 核心业务对象
- **任务（Issue）** - 工作单元，包含标题、描述、状态、优先级等信息
- **任务依赖（IssueDependency）** - 任务间的阻塞关系

### 前置条件
- 用户已配置至少一个助手
- 用户已配置仓库路径

---

## 模块边界

### 上游模块
| 模块 | 输入 |
|------|------|
| 助手配置 | 提供可选择的助手列表 |

### 下游模块
| 模块 | 输出 |
|------|------|
| 任务执行 | 任务被指派给助手后，创建执行任务 |

### 数据边界
- 一个任务归属于一个工作空间
- 一个任务可以有零个或一个父任务（子任务）
- 一个任务可以有零个或多个依赖任务

### 职责边界
- 本模块不负责任务的实际执行
- 本模块不负责任务的进度跟踪（由任务执行模块负责）

## 核心流程与状态

### 任务状态流转

```
┌──────────┐     ┌──────────┐     ┌─────────────┐     ┌───────────┐     ┌──────────┐
│ backlog  │────►│   todo   │────►│ in_progress │────►│ in_review │────►│   done   │
└──────────┘     └──────────┘     └─────────────┘     └───────────┘     └──────────┘
     │               │                   │                                           │
     │               │                   │                                           │
     │               │                   ▼                                           │
     │               │              ┌──────────┐                                     │
     │               │              │ blocked   │◄──── 由其他任务阻塞                  │
     │               │              └──────────┘                                     │
     │               │                                                           │
     ▼               ▼                                                           ▼
┌──────────────────────────────────────────────────────────────────────────────────┐
│                                    cancelled                                     │
│                               用户主动取消                                          │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### 任务优先级

| 优先级 | 说明 | 使用场景 |
|--------|------|---------|
| urgent | 紧急 | 需要立即处理 |
| high | 高 | 本版本重要 |
| medium | 中 | 正常优先级 |
| low | 低 | 可以延后 |
| none | 无 | 未设置 |

### 任务依赖流转

```
任务依赖类型：
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Issue A blocks Issue B                                    │
│  ─────────────────────────                                  │
│  含义：A 完成前，B 不能开始                                  │
│  场景：API 接口依赖数据库设计                                 │
│                                                             │
│  Issue C blocked_by Issue D                                 │
│  ───────────────────────────                                │
│  含义：C 被 D 阻塞                                          │
│  场景：实现任务被设计任务阻塞                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 任务指派流程

```
用户创建任务
    │
    ├── 填写标题（必填）
    ├── 填写描述（可选）
    ├── 选择状态（默认 backlog）
    ├── 选择优先级（默认 none）
    ├── 选择助手（必填， assignee_type = 'agent'）
    └── 设置截止日期（可选）
         │
         ▼
    保存任务
         │
         ▼
    助手配置 → 助手状态为 idle/working
         │
         ▼
    任务状态为 todo
         │
         ▼
    任务执行模块领取任务
```

## 功能点

### 功能 1：创建任务

**功能目标/解决的问题**
用户需要创建新的工作任务，分配给 AI 助手处理。

**前置条件**
- 用户已登录
- 已配置至少一个助手

**业务规则**
- 标题为必填项，长度 1-500 字符
- 描述为选填，最长 50000 字符
- 状态默认为 backlog
- 优先级默认为 none
- 必须选择助手
- 截止日期为可选

**业务数据**
- 任务标题：简明扼要描述要做什么
- 任务描述：详细说明任务内容、验收标准等
- 任务状态：当前所处阶段
- 优先级：紧急程度
- 助手：指派执行此任务的 AI 助手
- 截止日期：任务完成截止时间

**交互流程**
1. 用户点击「新建任务」按钮
2. 系统弹出任务创建弹窗
3. 用户填写表单
4. 用户点击「保存」按钮
5. 系统验证必填字段
6. 保存成功后关闭弹窗，刷新列表显示新任务

**异常与边界**
- 标题为空：提示「标题不能为空」
- 标题超长：提示「标题不能超过 500 字符」
- 未选择助手：提示「请选择助手」
- 数据库保存失败：提示「创建失败，请重试」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 创建成功 | E2E | 填写所有必填字段，点击保存 | - |
| 标题必填 | E2E | 标题为空时保存 | 空白字符串 |
| 标题长度限制 | 单元测试 | 标题 501 字符 | 超长字符串 |
| 默认值正确 | 单元测试 | 不填写状态、优先级，查看默认值 | - |
| 助手必选 | E2E | 不选择助手时保存 | 未选择 |

### 功能 2：编辑任务

**功能目标/解决的问题**
用户需要修改已存在任务的信息。

**前置条件**
- 任务存在
- 任务状态不为 done/cancelled（已完成/已取消的任务不可编辑）

**业务规则**
- 标题、描述、状态、优先级、助手均可修改
- 已完成/已取消的任务不可编辑
- 其他状态下可任意修改

**交互流程**
1. 用户点击任务列表中的「编辑」按钮
2. 系统弹出编辑弹窗，预填当前数据
3. 用户修改表单
4. 用户点击「保存」按钮
5. 系统保存修改
6. 关闭弹窗，刷新列表

**异常与边界**
- 已完成任务编辑：提示「已完成任务不可编辑」
- 已取消任务编辑：提示「已取消任务不可编辑」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 编辑成功 | E2E | 修改所有字段并保存 | - |
| 状态不可编辑 | E2E | 尝试编辑已完成任务 | done 状态 |
| 取消状态不可编辑 | E2E | 尝试编辑已取消任务 | cancelled 状态 |

---

### 功能 3：删除任务

**功能目标/解决的问题**
用户需要删除不需要的任务。

**前置条件**
- 任务存在
- 任务状态不为 in_progress/in_review（执行中/审核中的任务不可删除）

**业务规则**
- 删除任务会级联删除相关的任务依赖关系
- 删除任务不会删除执行历史
- 执行中/审核中的任务不可删除

**交互流程**
1. 用户点击任务列表中的「删除」按钮
2. 系统弹出确认对话框
3. 用户点击「确认删除」
4. 系统执行删除
5. 刷新列表

**异常与边界**
- 执行中删除：提示「任务执行中，不可删除」
- 审核中删除：提示「任务审核中，不可删除」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 删除成功 | E2E | 确认删除 | backlog 状态 |
| 执行中不可删除 | E2E | 尝试删除 in_progress 任务 | in_progress 状态 |
| 级联删除依赖 | 单元测试 | 删除任务后检查依赖表 | - |

---

### 功能 4：任务状态变更

**功能目标/解决的问题**
用户或系统需要变更任务状态以推进工作流。

**前置条件**
- 任务存在
- 新状态符合状态流转规则

**业务规则**
- 状态按照定义的流转图变更
- 任何状态均可变更为 cancelled
- blocked 状态可由用户手动解除
- 状态变更触发 WebSocket 广播

**交互流程**
1. 用户在任务详情或列表中选择新状态
2. 系统更新任务状态
3. WebSocket 广播状态变更事件

**异常与边界**
- 无效状态流转：提示「不允许的状态变更」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 状态流转正确 | 单元测试 | 按流转图测试所有路径 | 无效路径 |
| WebSocket 广播 | E2E | 状态变更后检查 WS 消息 | - |

---

### 功能 5：任务优先级变更

**功能目标/解决的问题**
用户需要调整任务的紧急程度。

**前置条件**
- 任务存在

**业务规则**
- 优先级可随时变更
- 优先级影响任务在队列中的排序

**交互流程**
1. 用户在任务详情或列表中选择新优先级
2. 系统更新任务优先级
3. WebSocket 广播优先级变更事件

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 优先级变更 | E2E | 选择不同优先级 | - |
| WebSocket 广播 | E2E | 优先级变更后检查 WS 消息 | - |

---

### 功能 6：任务指派给助手

**功能目标/解决的问题**
用户需要将任务分配给 AI 助手执行。

**前置条件**
- 任务存在
- 已配置至少一个助手

**业务规则**
- 一个任务只能指派给一个助手
- 指派后任务状态变为 todo
- 助手状态变为 working

**交互流程**
1. 用户在任务详情中选择助手
2. 系统更新任务的 assignee_id 和 assignee_type
3. 助手状态更新为 working
4. 任务执行模块开始轮询此任务

**异常与边界**
- 助手不可用：提示「助手当前不可用」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 指派成功 | E2E | 选择助手并保存 | - |
| 助手状态变更 | 单元测试 | 指派后检查助手状态 | - |
| 任务状态变更 | 单元测试 | 指派后任务状态为 todo | - |

---

### 功能 7：任务依赖管理

**功能目标/解决的问题**
用户需要设置任务之间的依赖关系，实现简单的任务编排。

**前置条件**
- 任务 A 和任务 B 都存在
- 任务 A 和任务 B 不存在循环依赖

**业务规则**
- 支持 blocks（阻塞）和 blocked_by（被阻塞）两种关系
- 不能创建循环依赖（A blocks B blocks C blocks A）
- 删除任务时自动删除相关依赖关系

**业务数据**
- 被依赖任务：当前任务所依赖的任务
- 依赖类型：blocks（阻塞别人）/ blocked_by（被别人阻塞）

**交互流程**
1. 用户在任务详情中点击「添加依赖」
2. 系统弹出任务选择弹窗
3. 用户选择被依赖的任务
4. 用户选择依赖类型
5. 系统验证无循环依赖
6. 保存依赖关系

**异常与边界**
- 循环依赖：提示「不能创建循环依赖关系」
- 自依赖：提示「任务不能依赖自己」

**验收标准**

| 验收项 | 验证方式 | 测试场景 | 边界条件 |
|-------|---------|---------|---------|
| 添加依赖成功 | E2E | 选择任务并添加依赖 | - |
| 循环依赖检测 | 单元测试 | A→B→C→A | 三任务循环 |
| 自依赖检测 | 单元测试 | A 依赖 A | 同一任务 |
| 删除时级联删除 | 单元测试 | 删除任务后检查依赖表 | - |

## 数据库设计

### 表结构

#### issue 表（任务）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | UUID | PK | 主键 |
| workspace_id | UUID | NOT NULL | 工作空间 ID（单人版固定） |
| title | TEXT | NOT NULL | 任务标题 |
| description | TEXT | | 任务描述 |
| status | TEXT | NOT NULL, CHECK | 状态 |
| priority | TEXT | NOT NULL, CHECK | 优先级 |
| assignee_type | TEXT | CHECK | 指派类型（agent/member） |
| assignee_id | UUID | | 指派对象 ID |
| creator_type | TEXT | NOT NULL | 创建者类型 |
| creator_id | UUID | NOT NULL | 创建者 ID |
| parent_issue_id | UUID | REFERENCES issue | 父任务 ID（子任务） |
| position | FLOAT | NOT NULL DEFAULT 0 | 排序位置 |
| due_date | TIMESTAMPTZ | | 截止日期 |
| created_at | TIMESTAMPTZ | NOT NULL | 创建时间 |
| updated_at | TIMESTAMPTZ | NOT NULL | 更新时间 |

**CHECK 约束：**
```sql
status IN ('backlog', 'todo', 'in_progress', 'in_review', 'done', 'blocked', 'cancelled')
priority IN ('urgent', 'high', 'medium', 'low', 'none')
assignee_type IN ('agent', 'member')
creator_type IN ('agent', 'member')
```

#### issue_dependency 表（任务依赖）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | UUID | PK | 主键 |
| issue_id | UUID | NOT NULL, REFERENCES issue | 任务 ID |
| depends_on_issue_id | UUID | NOT NULL, REFERENCES issue | 被依赖的任务 ID |
| type | TEXT | NOT NULL, CHECK | 依赖类型 |

**CHECK 约束：**
```sql
type IN ('blocks', 'blocked_by', 'related')
```

### 索引

```sql
CREATE INDEX idx_issue_workspace ON issue(workspace_id);
CREATE INDEX idx_issue_assignee ON issue(assignee_type, assignee_id);
CREATE INDEX idx_issue_status ON issue(workspace_id, status);
CREATE INDEX idx_issue_priority ON issue(workspace_id, priority);
CREATE INDEX idx_issue_parent ON issue(parent_issue_id);
CREATE INDEX idx_dependency_issue ON issue_dependency(issue_id);
CREATE INDEX idx_dependency_depends ON issue_dependency(depends_on_issue_id);
```
