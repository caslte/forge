## CE-S11 新增用例（自 E-CE-30 起，编号接既有 E-CE-29）

### E-CE-30 · 历史视图加载冒烟（**B3 加载基线，P0 门禁**）

- **关联 AC**：AC-CE-032、AC-CE-035 ｜ **优先级**：P0 ｜ **上线门禁**：是
- **自动化等级**：`mock-backend`
- **角色**：本地单用户 ｜ **页面**：代码浏览器左栏
- **前置**：项目已注册；`window.__forgeMock.seed('git/getCommitLog', ...)` 注入 8 条跨 3 位作者的提交（含 1 条 merge、1 条 root）；`git/getCommitDetail`、`git/getCommitFileDiff` 同步 seed
- **操作**：进入代码态 → 点「历史」tab
- **断言**：
  1. **健康**：无 console error / pageerror / requestfailed；不崩不空白
  2. **可见性**：提交行、头像、日期分隔条均可见；无重叠、无溢出、无错位
  3. **内容**：行数 = 注入条数；「合并」标记恰在 merge 那条
  4. **分隔条**：`今天`/`昨天`/`M月D日` 顺序正确
- **失败检查**：任一断言不过即红；失败证据 = `.app` 截图 + console 日志
- **可自动化性**：全自动

### E-CE-31 · 提交人展示（本需求核心诉求）

- **关联 AC**：AC-CE-033 ｜ **优先级**：P0 ｜ **上线门禁**：是 ｜ **自动化等级**：`mock-backend`
- **前置**：注入「陈默/王工/李工」三位作者的提交（**故意制造中文名末字相同的情形**）
- **操作**：打开历史视图
- **断言**：
  1. 每行显示 `说明 + 头像 + 姓名 + 相对时间 + 短SHA` 五项，顺序固定
  2. **三个中文头像的首字两两不同**（陈/王/李）—— 若实现取末字，此条必红
  3. 同一作者的多次提交，头像底色**完全相同**（`getComputedStyle` 取 background-color 精确比较）
  4. **零网络请求**：监听 `page.on('request')`，历史视图加载期间不得出现任何 `gravatar`/头像外域请求
  5. 相对时间复用 `project.timeXxx`，中英切换后文案随之切换（不是硬编码）
- **负向断言**：姓名不得被截断成「陈…」（292px 宽度下仍须完整可读）

### E-CE-32 · 历史列表筛选

- **关联 AC**：AC-CE-034 ｜ **优先级**：P1 ｜ **自动化等级**：`mock-backend`
- **操作**：在筛选框输入作者名片段 → 观察列表；再输入不存在的关键词
- **断言**：命中项过滤正确；**无匹配时给明确空态**（不空白、不报错）；清空后恢复全量

### E-CE-33 · 提交详情头部

- **关联 AC**：AC-CE-036 ｜ **优先级**：P0 ｜ **自动化等级**：`mock-backend`
- **操作**：点第一条提交
- **断言**：右栏出现头部，含姓名 / email（`<…>` 包裹）/ 绝对时间 / 短 SHA；merge 提交额外显示「合并」，root 显示「首次提交」；正文非空时完整展示（保留换行）；「复制 SHA」按钮点击后剪贴板内容 = 完整 40 位 sha

### E-CE-34 · 两级取数时序（本模块最重要的性能断言）

- **关联 AC**：AC-CE-037 ｜ **优先级**：P0 ｜ **上线门禁**：是 ｜ **自动化等级**：`mock-backend`
- **前置**：注入一个含 8 个文件的提交；统计 bridge 调用次数
- **操作**：选中提交 → **不展开任何文件** → 展开文件 1 → 展开文件 2 → 折叠文件 1 → 再展开文件 1
- **断言**：
  1. 选中后：`getCommitDetail` 调用 1 次，**`getCommitFileDiff` 调用 0 次**
  2. 展开文件 1：`getCommitFileDiff` 调用 1 次，参数含该文件路径
  3. 展开文件 2：再 +1 次，**不重复调用文件 1**
  4. 折叠再展开文件 1：**命中缓存，调用数不增**
- **负向断言**：全程**不得**出现一次性拉全量 patch 的调用；`getCommitDetail` 的响应体中不得含 `diff` 字段
- **RED 探针**：把 `getCommitDetail` mock 改成同时返回 patch → 断言 1 红

### E-CE-35 · 空态两态

- **关联 AC**：AC-CE-040、AC-CE-041 ｜ **优先级**：P0 ｜ **上线等级**：`mock-backend`
- **场景 A（空仓库）**：seed `git/getCommitLog` 返回 `{ commits: [], hasMore: false }`
- **场景 B（非 Git 项目）**：seed `getStatus` 返回 `isGitRepo: false`
- **断言**：
  1. 两种情况各给**明确中文文案**，非空白、非报错弹窗
  2. **筛选框一并收起**（没有可筛的东西时留一个永远筛不出结果的框是噪声）
  3. 右栏空态提示「选择左侧的一条提交查看详情」
  4. **健康**：无 console error；空态**不得**由异常路径触发（若出现未捕获异常即红）

### E-CE-36 · 并排 diff 渲染

- **关联 AC**：AC-CE-036 ｜ **优先级**：P0 ｜ **自动化等级**：`mock-backend`
- **前置**：seed 单文件 unified diff（含增行/删行/上下文）
- **操作**：选中提交 → 展开某文件
- **断言**：并排两列渲染；增行底色 = `--success` 派生、删行 = `--destructive` 派生；行号与 diff 内容一致；大 diff 按 `INITIAL_ROWS=200` 折叠并有「展开全部」

### E-CE-37 · 分页加载

- **关联 AC**：AC-CE-044 ｜ **优先级**：P1 ｜ **自动化等级**：`mock-backend`
- **操作**：滚动到列表底部
- **断言**：`hasMore=true` 时追加下一页；追加后**无重复行**（按 sha 计数）；末页不再请求

## 通用约束

- **后端为 mock**：CE-S11 的三个 `mock-bridge.ts` case 是必做项（`git/getCommitLog` / `git/getCommitDetail` / `git/getCommitFileDiff`），
  不补则全部 CE-S11 用例无数据可跑
- **几何断言**：沿用既有 `getBoundingClientRect` + `getComputedStyle` 口径；**禁止**用 `boundingBox()` 紧跟点击读值
  —— 过渡未结束时读到的是中间帧（既有 changelog v6.x 已记录该坑，需 `getAnimations().finished` 或轮询等落定）
- **失败证据**：每条失败保留截图 + console 日志 + mock 种子，便于复现
- **主题**：涉及色值的断言（头像同色、增删行底色）须在**双主题各跑一遍**，暗色下 token 会切换
