# 07 版本更新与安装包（pi 运行时）接口

> 模块：设置页「版本更新」分区后端（明面为 forge 产品更新；内部实现走 pi 运行时）。
> 来源：PRD 07（docs/prd/07_installer_update.md，含安装包与联动更新场景；本文档当前覆盖已实现部分，安装包/自更新相关接口待实现时扩展）。
> 状态：已确认（v1：版本展示 + 内置组件清单 + 更新组件）。

## 0. 业务对象与背景

- **forge 版本**：产品版本号（`app.getVersion()`），随 forge 发版更新。
- **内置组件**：`~/.pi/agent` 共享扩展（settings.json `packages` 清单 + `npm/` npm 工程实体）。
  终端 pi（若安装）与 forge 共用同一份；forge 更新组件对两端同时生效。
- **更新实现**：不依赖用户安装全局 pi——用 Electron 主进程可执行文件以
  `ELECTRON_RUN_AS_NODE=1` 运行内置引擎 CLI（`dist/bundle/cli.js`）的
  `pi update --extensions --no-approve`（超时 10 分钟）。
- **不做**（后续 PRD 另立项）：全局 pi CLI 检测/更新、forge 应用自更新、安装包预装插件。

## 1. pi/getInfo

读取 forge 版本。**无参数**。

响应 `data`：

```json
{ "forgeVersion": "0.1.0" }
```

| 字段 | 类型 | 说明 |
|---|---|---|
| forgeVersion | string | forge 产品版本 |

附加行为：
- **不返回组件清单**（原型确认 2026-09-08：设置页不展示组件，明细走结构化日志与 updater-state.json 的 components 快照）；共享扩展读取逻辑保留在服务层内部供日志使用，settings.json 缺失/损坏静默降级不报错。

## 2. pi/updatePlugins

更新内置组件（等价终端 `pi update --extensions`）。**无参数**。同步等待（前端按钮 busy 态）。

成功响应 `data`：

```json
{ "output": "updated 3 packages" }
```

失败响应（`code=6002`）：

```json
{
  "code": 6002,
  "message": "组件更新失败",
  "data": { "output": "npm error code E404\nnpm error 404 Not Found" }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| output | string | 更新器 stdout/stderr 尾部（≤4000 字符），成功供回显、失败供排查 |

附加行为：
- 内置 CLI 缺失（打包裁剪等）→ 直接 6002，`output` 为中文原因，不 spawn。
- 超时（10 分钟）/非零退出 → 6002；输出取 stderr 优先拼接尾部。
- 更新完成后 UI 刷新 toast；**组件变更明细（包名 · 旧版本 → 新版本）由服务层写结构化日志并刷新 updater-state.json 的 components 快照**（UI 不再展示清单，无需重拉）。

## 3. 应用自更新（IN-S03，待开发部分契约）

承载 forge 应用自更新的 UI 交互（PRD 07 §3.4：发现新版提示 + 手动点击更新 + 下载进度 + 重启安装）。
预装（IN-S02）与联动更新（IN-S04）**无 RPC**——后台静默执行，不经 UI。
状态机：`idle → checking → found → downloading → downloaded → installing`，任一失败回 `idle`（静默可重试）。

### 3.1 updater/getState

查询当前自更新状态快照。**无参数**。

响应 `data`：

```json
{
  "status": "idle",
  "currentVersion": "0.1.0",
  "latestVersion": null,
  "downloadProgress": null,
  "error": null
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| status | string | idle / checking / found / downloading / downloaded / installing |
| currentVersion | string | 当前 forge 版本 |
| latestVersion | string \| null | 检测到的新版本号（found 之后有值） |
| downloadProgress | number \| null | 下载进度 0-100（downloading 时有值） |
| error | string \| null | 最近一次失败原因（静默展示用，不主动弹错） |

### 3.2 updater/checkForUpdates

触发一次更新检查（启动时由壳层自动调用 + 设置页分区打开/手动触发）。**无参数**。

响应 `data`：同 `updater/getState`（检查完成后的状态快照；found 时 latestVersion 有值）。

- feed 不可达/网络失败 → `6003`（UI 捕获后静默，不弹错，符合 PRD 降级要求）。
- 无新版 → `code 0`，`status=idle`、`latestVersion=null`（不发提示）。

### 3.3 updater/downloadUpdate

开始下载新版本（仅 `status=found` 时有效；重复调用返回当前状态幂等）。**无参数**。

响应 `data`：同 `updater/getState`（`status=downloading` 起步，进度经事件推送）。

- 下载失败/校验失败 → `6004`，状态回 `idle` 静默（AC-IN-010/011）。

### 3.4 updater/quitAndInstall

安装已下载的更新并重启应用（仅 `status=downloaded` 时有效）。**无参数**。

响应：成功则应用退出重启（**本调用正常不返回**）；安装启动失败 → `6005`，状态回 `idle`。

## 4. 事件

| 事件 | payload | 触发时机 |
|---|---|---|
| `updater.stateChanged` | `{ status, currentVersion, latestVersion, downloadProgress, error }`（结构与 getState.data 一致） | 自更新状态机任意跃迁：检查开始/完成、发现新版、下载进度（百分比步进）、下载完成、安装启动、失败回 idle |

> 落地提示：新事件必须登记 `ipc-contract.ts` 的 `FORGE_EVENTS` 白名单（主进程只转发白名单内事件，
> 漏登在真实 Electron 端静默丢失——见 docs/knowledge/ipc-events-whitelist.md）；mock-bridge 需补默认 mock。

## 5. 错误码

| code | 场景 |
|---|---|
| 6002 | 组件更新失败（CLI 缺失/超时/非零退出；data.output 附输出尾部） |
| 6003 | 应用更新检查失败（feed 不可达/网络失败；UI 静默处理） |
| 6004 | 应用更新下载失败/校验失败（状态回 idle 静默） |
| 6005 | 应用更新安装启动失败（状态回 idle） |
